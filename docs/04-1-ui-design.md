# KubeGuardian AI — UI 디자인 (보고서 화면)

> [UI 정의서](04-ui-spec.md) §6의 보고서 화면(점검 이력 · 이슈 · 점검 구성 세 페이지, 점검 상세 · 이슈 상세 · 보고서, 근거 서랍, 이력 질의 채팅 패널)을 **그리기 위한** 디자인 문서다. 기능·데이터·라우트·용어는 정의서가 정본이고, 이 문서는 "무엇이 어디에 어떻게 보이는가"를 정한다. 둘이 어긋나면 정의서를 따른다.
> 기준: 기획서 v3.2 + 결정 이력 10-27까지(10-26~27 화면 구조 재구성), [규칙 명세 05-rules.md](05-rules.md). Claude Design으로 목업을 그릴 때 이 문서를 입력으로 쓴다 (§8).
> Slack 메시지 목업은 범위 밖이다. 메시지 형식은 [UI 정의서 §2](04-ui-spec.md#2-메시지-정의)를 본다.
> 화면 톤(색·글꼴·아이콘·배지)은 **톤 보드 확정안(2026-10-22)** 이 기준이다 (§2). 다크 모드 토큰은 보류다.
> 용어는 정의서 [§0·§1.3](04-ui-spec.md#0-원칙)을 따른다: **점검**(5분마다 또는 직접 남는 관측 기록) · **이슈**(장애 신호·증상이 이어지는 동안 하나로 묶이는 단위, 코드 이름 `incident`) · **문제**(보고서 안의 선별 항목, 최대 3건). 점검 결과에 "이상"이라는 값은 없고 "이슈 열림·이어짐·해결·이상 없음"으로 말한다.

## 0. 목적과 범위

| 항목 | 내용 |
|---|---|
| 목적 | 운영자가 Slack 알림의 링크로 들어와 **원인·근거·조치를 한 화면에서 읽고**, 점검 이력과 조사 과정으로 결론을 믿어도 되는지 확인한다 |
| 그리는 화면 | **점검 이력(홈)** `/p/{p}/checks`, 점검 상세 `/p/{p}/checks/{run}`(조사 과정 포함), **이슈** `/p/{p}/issues`와 이슈 상세, 보고서 단독 페이지 `/p/{p}/reports/{id}`, **점검 구성** `/p/{p}/setup`, 근거 서랍(`?ev=N`), 이력 질의 채팅 패널 ([정의서 §6.3](04-ui-spec.md#63-페이지와-주소)). 점검 상세·이슈 상세는 목록 오른쪽 패널로 열리는 한 페이지 구조다 (탭 없음). 별도의 보고서 목록·조사 과정 페이지는 없다 |
| 범위 밖 | Slack 메시지 목업, 로그인·프로젝트 선택 화면, 모바일 전용 화면, 증상 입력 조사 폼 |
| 화면 성격 | **점검 시점에 고정된 판정 근거를 읽는 문서형 화면.** 상태 대시보드가 아니다. 차트·실시간 그래프·리소스 탐색이 없다. 질의 채팅은 저장된 이력만 읽는다 ([정의서 §6.9](04-ui-spec.md#69-경계)) |
| 사용 환경 | 업무 노트북 브라우저 1280~1440px 기준. 960px 이하에서도 깨지지 않아야 한다 (모바일 최적화는 아님). 발표 때 화면을 투사하므로 글자가 작아 보이지 않아야 한다 |
| 구현 | 서버 렌더링 HTML(Jinja2 + HTMX). 디자인은 CSS 변수와 표준 HTML 요소로 구현할 수 있는 범위로 그린다 (프론트 프레임워크 없음. 아이콘은 Lucide SVG 몇 개를 인라인으로 쓴다, §5.24. 글꼴은 Google Fonts, §3.1) |
| 화면 톤 | **톤 보드 확정안(2026-10-22)**: 문서처럼 읽히는 점검 보고서. 차가운 회색 바탕에 청록 강조, 흙색·이끼색 상태색, 선형 SVG 아이콘과 각진 배지. 색은 의미에만 쓰고 정상은 조용하게 (§2·§5) |

## 1. 디자인 원칙

| # | 원칙 | 그림에서 지키는 법 |
|---|---|---|
| 1 | **문서처럼 읽힌다** | 위에서 아래로 한 열로 읽는다. 카드를 겹겹이 쌓지 않고, 제목·본문·표로 구성한다. 한 줄 길이는 본문 기준 약 70자를 넘기지 않는다 |
| 2 | **색은 의미에만 쓴다** | 청록(accent) = 클릭할 수 있는 것(링크·버튼·근거 칩)과 진행 중. 상태색 = 심각도·상태만. 장식용 그라데이션·색 배경 영역을 만들지 않는다 |
| 3 | **정상은 조용하다** | 통과·정상·해결은 회색 글자와 작은 표시로 줄인다. 눈에 띄는 색은 적발·긴급·주의·확인 못함에만 쓴다 |
| 4 | **근거 번호가 항상 눈에 띈다** | `[근거 N]` 칩은 고정폭 글자와 accent 색 1px 테두리 사각형으로, 문장 끝에서 바로 찾을 수 있다. 근거가 없는 문장은 _(추정)_ 이 붙어 다르게 보인다 |
| 5 | **심각도는 색만으로 구분하지 않는다** | 심각도·상태는 항상 선형 SVG 아이콘과 라벨 글자를 함께 쓴다 (색각 이상, 흑백 인쇄, 투사 화면 대비) |
| 6 | **밀도는 높게, 위계는 분명하게** | 한 화면에 많은 정보를 담되, 제목 → 결론 → 근거 순으로 크기·굵기 차이로 위계를 만든다. 간격은 4px 배수만 쓴다 |

## 2. 색 테마

**톤 보드 확정안(2026-10-22)이 정본이다.** 문서처럼 읽히는 점검 보고서: 차가운 회색 바탕(Console 중립색)에 청록(Deep Teal) 강조, 흙색·이끼색 상태색, 선형 SVG 아이콘과 각진 배지. 색은 의미에만 쓰고 정상은 조용하게 둔다.

**라이트가 기본이고, OS가 다크 설정이면 다크로 자동 전환한다** (`prefers-color-scheme: dark`). 사용자가 고르는 토글은 두지 않는다. 다크 토큰 값은 아직 없다 (§2.6).

### 2.1 바탕·글자·강조

대비는 WCAG 상대 휘도 기준 비율이다 (계산 방법은 §2.5). 기준: 본문·작은 글자 4.5:1 이상.

| 토큰 | 값 | 용도 | 대비 |
|---|---|---|---|
| `--bg` | `#eef0f4` | 페이지 바탕 (Console 중립색) | ink 위 15.6 |
| `--surface` | `#ffffff` | 본문 면, 표, 서랍 | ink 위 17.79 |
| `--surface-2` | `#e4e7ee` | 코드·근거 원문 블록, 호버, 비활성 버튼 | ink 위 14.37 |
| `--line` | `#cfd4de` | 구분선, 테두리, 진행 막대 바탕 | — (글자 아님) |
| `--ink` | `#14181f` | 본문 글자 | 위 값 |
| `--muted` | `#566070` | 보조 글자, 메타, 통과 항목 | surface 위 **6.36**, bg 위 5.57, surface-2 위 5.14 |
| `--accent` | `#3f6a60` (Deep Teal) | 링크·버튼·근거 칩·**진행 중** (모두 같은 색) | surface 위 6.10, bg 위 5.35, accent-soft 위 4.90, 흰 글자/accent 버튼 6.10 |
| `--accent-soft` | `#dde9e6` | 현재 단계 행·진행 중 배지·호버 배경 | — |

### 2.2 상태색

상태마다 세 값을 둔다. **text**는 글자·아이콘 선·배지 테두리(작은 글자 가능), **dot**은 점·왼쪽 막대·진행도 막대(글자에 쓰지 않음), **soft**는 배지·배너 배경이다. 이모지는 쓰지 않고 §5.1의 선형 SVG 아이콘과 라벨을 함께 쓴다.

| 상태 | 설명 | 아이콘·라벨 | text | dot | soft | text/surface | text/soft | dot/surface |
|---|---|---|---|---|---|---|---|---|
| 긴급 | 벽돌빛 붉은색 | 팔각형 ! · 긴급 | `#a3332b` | `#c0473d` | `#f6e3e0` | 6.85 | 5.54 | 4.99 |
| 주의 | 황토·구운 주황 | 삼각형 ! · 주의 | `#8a4a12` | `#c27a2c` | `#f5e8d6` | 6.84 | 5.67 | 3.43 |
| 잠재 위험 | 올리브 머스터드 | 원 ! · 잠재 위험 | `#675a10` | `#9a8820` | `#f1edc9` | 6.89 | 5.81 | 3.55 |
| 개선 권고 | 이끼 낀 회색 | 원 i · 개선 권고 | `#4a5a5c` | `#7a8985` | `#e3e8e6` | 7.22 | 5.83 | 3.66 |
| 진행 중 | Deep Teal (강조색과 같음) | 회전 화살표 · 진행 중 | `#3f6a60` | `#52796f` | `#dde9e6` | 6.10 | 4.90 | 4.86 |
| 정상·복구 | 차분한 강청색 파랑 | 원 체크 · 정상·복구 | `#1f5c94` | `#3b82c4` | `#dfeaf5` | 6.96 | 5.71 | 4.06 |

- 모든 text 값이 흰 면(surface) 위에서 6:1 이상, 자기 soft 배경 위에서 4.9:1 이상이다. `--muted`는 surface 위 6.36이다.
- dot은 글자가 아니라 도형이므로 비텍스트 대비 기준(3:1)을 목표로 했다. 주의 3.43이 가장 낮다.
- 긴급·주의·잠재 위험은 색이 비슷한 계열이라 **아이콘 모양(팔각형·삼각형·원)과 라벨 글자를 항상 함께 쓴다.** 색만으로 구분하지 않는다.
- 진행 중은 별도 색을 만들지 않고 `--accent`를 쓴다. "클릭할 수 있음"과 "진행 중"이 같은 색이므로, 진행 중은 항상 아이콘과 라벨을 붙이고 클릭 대상에는 밑줄·테두리를 둔다.

**이전 안에서 바뀐 점**

| 항목 | 이전 | 확정안 |
|---|---|---|
| 바탕 | 따뜻한 흰색 `#f7f7f5` | 차가운 회색 `#eef0f4` |
| 강조·링크·버튼·근거 칩 | 파랑 `#2f5bea` | Deep Teal `#3f6a60` |
| 진행 중 | 강조 파랑 | 강조색 Deep Teal (같은 색, 항상 아이콘·라벨 동반) |
| 정상·복구 | 초록 | **강청색 파랑** `#1f5c94`. **초록은 쓰지 않는다** |
| 긴급·주의·잠재 위험·개선 권고 | 선명한 빨강·주황·노랑·회색 | 벽돌·황토·올리브·이끼 회색 (흙색·이끼색) |
| 심각도·상태 표시 | 이모지 + 라벨 | 선형 SVG 아이콘 + 라벨 (§5.1) |
| 배지 모양 | 알약(999px) | 각진 배지(24px · 3px · 테두리 2px, 왼쪽 6px) |
| 글꼴 | Pretendard | IBM Plex Sans KR · IBM Plex Mono |
| 토큰 이름 | `--crit-text`처럼 `-text` 접미사 | `--crit`(text)·`--crit-dot`·`--crit-soft`. 접두사 crit·warn·risk·tip·ok |
| 다크 모드 값 | 있음 | 보류 |

### 2.3 특수 상태의 표시

색 하나로 만들지 않고 테두리·아이콘·배경 조합으로 구분한다.

| 상태 | 표시 | 이유 |
|---|---|---|
| 점검·조사의 보조 상태 (조사 중, 조사 미완, 조사 실패, 점검 중단, 일부 확인하지 못함) | **심각도 색을 쓰지 않는다.** 작은 글자 + 선형 아이콘만, 색은 ink·muted·accent (§5.1 보조 표시) | 정의서 §1.3: 점검·조사 상태는 심각도와 다른 축이라 같은 배지 모양·색을 쓰면 뜻이 섞인다 |
| 관찰 중 | **점선** 테두리 + 왼쪽 굵은 선 + 지속 시간 진행도(예: `15분 중 10분째`와 가는 막대) | 아직 적발이 아니므로 상태색을 쓰지 않는다 |
| 확인하지 못함 | 개선 권고 회색(`--tip`) 배지 + ⊘ 아이콘 + 못 읽은 kind·사유 | 통과도 적발도 아님. 읽지 못했다는 사실이 보여야 한다 |

### 2.4 CSS 변수

```css
:root{
  --bg:#eef0f4; --surface:#ffffff; --surface-2:#e4e7ee; --line:#cfd4de;
  --ink:#14181f; --muted:#566070; --accent:#3f6a60; --accent-soft:#dde9e6;
  --crit:#a3332b; --crit-dot:#c0473d; --crit-soft:#f6e3e0;
  --warn:#8a4a12; --warn-dot:#c27a2c; --warn-soft:#f5e8d6;
  --risk:#675a10; --risk-dot:#9a8820; --risk-soft:#f1edc9;
  --tip:#4a5a5c;  --tip-dot:#7a8985;  --tip-soft:#e3e8e6;
  --ok:#1f5c94;   --ok-dot:#3b82c4;   --ok-soft:#dfeaf5;
}
```

진행 중은 `--accent`·`--accent-soft`를 그대로 쓴다 (`--accent-dot`은 `#52796f`로 진행도 막대에 쓴다).

### 2.5 대비 검증

임시 Python 스크립트로 WCAG 2.x 상대 휘도 공식에 따라 위 표의 모든 쌍을 계산했다 (스크립트는 레포 밖에 있고 커밋하지 않았다). 값을 바꾸면 같은 계산으로 다시 확인한다. 기준은 text 쌍 4.5:1 이상, `--muted` on `--surface` 4.5:1 이상이다.

### 2.6 다크 모드

**보류 — 실제 화면 확정 뒤 같은 방식(톤 보드)으로 정한다.** "라이트 기본, OS 다크 설정이면 다크 자동"이라는 결정은 유지하지만 다크 토큰 값은 아직 없다. 이전 다크 값은 새 팔레트와 맞지 않아 지웠다. 그때까지 목업은 라이트만 그린다 (§8.1).

## 3. 타이포그래피·간격

| 표 행 높이 | 최소 44px (세로 패딩 12px) |
| 모서리 반경 | **배지·근거 칩 3px**, 입력 6px, 버튼·표 윤곽 8px, 카드·서랍 12px, 알약(필터·맥락 칩·종류 표시) 999px |
| 구분 방식 | **1px `--line` 테두리 위주.** 그림자는 근거 서랍(`0 0 32px rgba(0,0,0,.18)`)과 채팅 패널(`0 0 16px rgba(0,0,0,.10)`)에만 쓴다 |
| 포커스 | 2px `--accent` 윤곽, 오프셋 2px. 키보드로 모든 칩·버튼·행에 접근한다 |

## 4. 기본 레이아웃

> 와이어프레임의 이모지는 자리 표시이고, 실제 화면에서는 §5.1의 SVG 아이콘 배지다. 구조(레일·GNB·목록-상세 분할·채팅 패널)는 [정의서 §6.2](04-ui-spec.md#62-전체-레이아웃)가 정하고, 이 절은 치수와 모양을 정한다.

### 4.1 전체 틀

```text
┌────┬───────────────────────────────────────────────────────────────────────────────┐
│ KG │ dev · minikube        마지막 점검 14:15 ✓ · 다음 14:20   [▶ 지금 점검] [질문] (○) │ GNB 56px
├────┼───────────────────────────────────────────────────────────────────────────────┤
│ ▤  │ 열린 이슈 [긴급 1] [주의 0]                                  [설정 확인 필요 1] │ 상단 띠 40px
│    ├──────────────────────────────┬────────────────────────────────────────────────┤
│ ◎  │ 목록 (420px)                 │ 상세 패널                                       │
│    │  필터 막대                    │  헤더: 제목 · 빵부스러기                         │
│ ⚙︎  │  행 · 행 · 행 …              │  절 바로가기: 조치 · 판정 · 조사 · 근거           │
│    │                              │  본문 (최대 폭 840px)                            │
│ ›  │                              │                                                │
└────┴──────────────────────────────┴────────────────────────────────────────────────┘
 레일 56px: 점검 이력 · 이슈 · 점검 구성(설정 확인 필요면 점) · 맨 아래 펼치기
```

| 영역 | 내용 |
|---|---|
| 아이콘 레일(LNB) | 폭 56px, 화면 높이 전체, `--surface` 배경, 오른쪽 1px `--line`. 맨 위 56px 칸이 로고(`KG` 글자 마크, 600 16px, **홈(점검 이력) 링크**). 그 아래 메뉴 3개 (§5.15). 레일 없는 화면은 없다 |
| GNB | 레일 오른쪽의 높이 56px 가로 바, `--surface` 배경, 아래 1px `--line`, 스크롤해도 고정. **전역 정보만** 둔다. 이동 탭은 없다 (§4.2) |
| 상단 띠 | GNB 아래 높이 40px, `--bg`와 같은 배경에 아래 1px `--line`. 열린 이슈 수와 설정 확인 필요 (§5.16). 스크롤해도 고정 |
| 본문 | 상단 띠 아래 남은 영역. **목록-상세 분할**: 목록 420px(최소 360px) + 상세 패널 나머지. 목록은 항상 남는다. 상세 안의 본문은 최대 폭 840px, 왼쪽 정렬, 좌우 24px |
| 목록 | `--surface` 배경, 오른쪽 1px `--line`, 자체 세로 스크롤. 위에 필터 막대(고정), 아래에 행 (§5.17~5.19). 보던 필터·스크롤은 상세를 열고 닫아도 그대로다 |
| 상세 패널 | `--bg` 바탕 위에 문서형 본문. 자체 세로 스크롤. 아무 행도 고르지 않았을 때는 muted 한 줄 `점검을 선택하면 여기에 상세가 열립니다.` (이슈 페이지는 `이슈를 선택하면 …`) — 첫 행을 자동으로 열지는 않는다 (판단) |
| 점검 구성 | 목록이 없는 한 열 페이지. 본문 최대 폭 960px (§6.6) |

### 4.2 GNB

```text
dev · minikube │                  마지막 점검 14:15 ✓ · 다음 14:20 │ [▶ 지금 점검] [? 질문] (○)
```

| 위치 | 내용 |
|---|---|
| 왼쪽 | 프로젝트 표시: 고정폭 알약 `dev · minikube`(`--surface-2`, 13px). **누를 수 없다** (포인터·화살표·호버 없음). 지금은 하나뿐이고 선택 화면을 그리지 않는다 |
| 가운데 | 비운다 |
| 오른쪽 1 | 마지막·다음 점검 시각 한 줄 (muted 13px, 시각은 고정폭). 앞에 마지막 점검 상태 아이콘: 이상 없음 `circle-check`(정상 색), 점검 중 `loader`(accent). 열린 이슈가 있어도 여기에는 색을 더하지 않는다 (그건 상단 띠의 일이다). **점검이 멈췄으면** 이 줄이 `점검 15분째 안 됨 · 마지막 정상 14:05`로 바뀌고 `triangle-alert` 아이콘 + ink 굵은 글자로 보인다 (점검 상태는 보조 표시라 심각도 색을 쓰지 않는다, §5.1) |
| 오른쪽 2 | **`▶ 지금 점검` 버튼** (§5.8) |
| 오른쪽 3 | **`질문` 버튼** (§5.22). 이력 질의 채팅 패널을 열고 닫는다 |
| 오른쪽 끝 | 사용자 자리: 지름 32px 빈 원(`--surface-2`, `user` 아이콘 muted). 누를 수 없다. 평가 결과·Phoenix 링크는 **설정이 있을 때만** 이 자리를 눌러 여는 작은 메뉴에 들어간다 (그때만 포인터·호버가 생긴다) |

- **탭을 두지 않는다.** 페이지 이동은 레일만 한다. 홈으로 돌아가는 길은 로고와 레일의 첫 메뉴다.

### 4.3 점검 상세·이슈 상세 패널의 틀

탭 없는 한 페이지다. 위에서 아래로 한 번에 읽히고, 절 바로가기는 같은 페이지 안의 이동일 뿐이다.

```text
dev › 점검 이력 › 10/26 14:05                                   ← 빵부스러기 (13px, muted)
점검 10/26 14:05                                               ← 페이지 제목 (24px)
조치 · 판정 · 조사 · 근거                                       ← 절 바로가기 (한 줄, sticky)
────────────────────────────────────────────────────────────
① 상태 머리
② 권장 조치
③ 점검 판정
④ 조사
⑤ 근거
```

| 항목 | 규칙 |
|---|---|
| 빵부스러기 | 상세 패널 맨 위. 마지막 항목이 현재 위치(링크 아님), 앞 항목은 accent 링크. 좁은 화면에서 상세가 전체 화면이 되면 `‹ 점검 이력` 되돌아가기 링크가 앞에 붙는다 |
| 절 바로가기 | 제목 아래 한 줄. `조치 · 판정 · 조사 · 근거` 글자 링크(accent, 14px)를 가운뎃점으로 이어 붙인다. **탭처럼 보이는 밑줄 막대·테두리·선택 배경을 쓰지 않는다.** 스크롤하면 상세 패널 위쪽에 붙고(`position: sticky`), 해당 절이 없는 상황(이상 없음 등)에서는 그 글자를 빼고 보인다 |
| 절 제목 | 18px 600, 앞에 ink 사각형 ■ (§3.2). 절 사이 32px |
| 이슈 상세 | 같은 틀. 절 바로가기는 `결론 · 타임라인 · 보고서` |
| 보고서 단독 페이지 | 상세 패널 틀만 쓰되 **목록 없이 본문 폭 840px 가운데** 한 열. 점검 상세의 ①②④와 같은 구성 (§6.5) |

### 4.4 근거 서랍

```text
┌─────────────────────── 화면 (스크롤 위치 유지) ──────────┬──── 서랍 520px ────┐
│ (배경이 어두워진다: 검정 40% 투명)                         │ [근거 14]       ✕  │
│                                                          │ log_excerpt        │
│                                                          │ 대상 / 수집 / 출처 │
│                                                          │ ┌────────────────┐ │
│                                                          │ │ 마스킹된 원문  │ │
│                                                          │ └────────────────┘ │
│                                                          │ 단독 페이지 링크 ⧉ │
└──────────────────────────────────────────────────────────┴────────────────────┘
```

| 항목 | 규칙 |
|---|---|
| 열기 | 어디서든 `[근거 N]`을 누른다 (점검 상세, 보고서, 이슈 상세의 보고서, 조사 과정의 도구 호출). 주소는 `?ev=N`이라 그대로 공유·새로고침이 된다 |
| 폭·위치 | 오른쪽에서 밀려 들어오는 520px 서랍, 높이는 화면 전체(GNB도 덮는다). 모서리 반경은 왼쪽 위·아래 12px |
| 배경 | 서랍 밖 영역을 검정 40% 투명으로 어둡게 한다. 아래 화면의 스크롤 위치와 선택은 그대로다 |
| 닫기 | **Esc**, 서랍 밖(어두운 영역) 클릭, 오른쪽 위 ✕ 버튼. 닫으면 주소의 `?ev=N`이 지워진다 |
| 단독 URL | 서랍 아래에 `단독 페이지 링크 복사` 버튼. 눌러 `?ev=N`이 붙은 주소를 복사하고 "복사했습니다"를 2초 보인다. 그 주소를 새 탭에서 열면 서랍이 열린 채 같은 화면이 나온다 |
| 채팅 패널과의 관계 | 서랍이 채팅 패널보다 위에 뜬다. 채팅의 `[근거 N]`은 서랍이 아니라 패널 안에서 펼쳐진다 (§5.23) |
| 960px 이하 | 서랍이 전체 폭을 차지한다 |

### 4.5 이력 질의 채팅 패널

```text
┌──── 목록 ────┬────────── 상세 패널 ──────────┬──── 채팅 패널 400px ──────┐
│              │                              │ 이력에 질문           ✕  │
│              │   (상세의 오른쪽 일부를       │ [이슈 #12 ✕] [필터 오늘 ✕] │
│              │    패널이 덮는다)             │ 저장된 이력만 읽습니다     │
│              │                              ├──────────────────────────┤
│              │                              │ (대화 영역, 세로 스크롤)   │
│              │                              ├──────────────────────────┤
│              │                              │ [ 질문 입력 (500자) ] ➤   │
└──────────────┴──────────────────────────────┴──────────────────────────┘
```

| 항목 | 규칙 |
|---|---|
| 겹침 | **본문을 밀어내지 않고 상세 패널 위에 겹친다** ([정의서 §6.7](04-ui-spec.md#67-이력-질의-채팅-패널)). 목록은 가려지지 않는다. 상단 바(GNB·상단 띠) 아래부터 화면 아래까지 오른쪽에 붙은 400px |
| 모양 | `--surface` 배경, 왼쪽 1px `--line`, 겹쳐 있다는 단서로 가벼운 그림자 `0 0 16px rgba(0,0,0,.10)` (서랍과 채팅 패널에만 그림자를 쓴다, 판단). 뒤를 어둡게 하지 않는다 |
| 열기·닫기 | GNB `질문` 버튼으로 열고 닫는다(열려 있으면 눌린 모양). 패널 오른쪽 위 ✕도 닫는다. Esc로는 닫지 않는다 (입력 중 실수 방지) |
| 유지 | 닫기 전까지 레일로 다른 페이지로 옮겨도 열려 있고 대화가 유지된다 |
| 맥락 | 열 때 보던 맥락(선택한 점검·이슈, 이력 필터)이 헤더 아래 칩으로 붙는다 (§5.22) |
| 링크 | 답변 안의 점검·이슈 링크를 누르면 **아래 화면**(목록-상세)이 그 대상으로 이동하고 패널은 열려 있다. 근거는 패널 안에서 펼친다 |
| 960px 이하 | 전체 폭 패널 (화면을 덮는다). 헤더의 ✕가 아래 화면으로 돌아가는 방법이다 |

### 4.6 960px 이하

| 영역 | 변화 |
|---|---|
| 레일 | 56px 그대로 (아이콘만, 펼치기 버튼은 숨긴다) |
| GNB | 프로젝트 표시와 점검 시각은 시각만 남기고, `지금 점검`·`질문`은 글자 없이 아이콘만 남긴다 (aria-label과 툴팁은 유지) |
| 상단 띠 | 한 줄 유지. 넘치면 설정 확인 필요가 아이콘 + 숫자로 줄어든다 |
| 본문 | **목록 또는 상세 한쪽만** 전체 폭으로 보인다. 목록에서 행을 누르면 상세가 전체 화면으로 열리고, 빵부스러기의 `‹ 점검 이력`으로 돌아온다. 보던 필터·스크롤은 그대로 |
| 점검 행 | 두 줄 구조 그대로 (§5.18). 가로 스크롤 없음 |
| 서랍·채팅 패널 | 전체 폭 |

### 4.7 페이지 이동 관계

```text
Slack M1(1차 감지)·M6 링크 ────────────▶ 점검 상세 (보고서가 아직 없을 수 있음)
Slack M1(원인 갱신)·M9 링크 ───────────▶ 같은 점검 상세 (보고서가 보임)
Slack M2 리마인더·M3 복구 링크 ────────▶ 이슈 상세
Slack M7 점검 중단 링크 ───────────────▶ 점검 이력
Slack M10 설정 확인 링크 ──────────────▶ 점검 구성 #health
로고 · `/` ────────────────────────────▶ 점검 이력 (홈)
레일 ──────────────────────────────────▶ 점검 이력 · 이슈 · 점검 구성
상단 띠 열린 이슈 ─────────────────────▶ 이슈 목록 (그 심각도 필터)
상단 띠 설정 확인 필요 ────────────────▶ 점검 구성 #health
GNB ▶ 지금 점검 ───────────────────────▶ 새 점검 상세 (진행 중, 목록 맨 위에 새 행)
GNB 질문 ──────────────────────────────▶ 채팅 패널 (보던 맥락 첨부, 어느 화면에서나)
점검 행 ─────────────────────────────▶ 오른쪽에 점검 상세 열림 (목록 유지)
점검 상세 ── 이슈 #12 칩 ──────────────▶ 이슈 상세
점검 상세 ── [근거 N] ─────────────────▶ 근거 서랍
이슈 행 ─────────────────────────────▶ 오른쪽에 이슈 상세 열림
이슈 상세 ── 타임라인의 점검 ──────────▶ 점검 상세
이슈 상세 ── 보고서 목록의 보고서 ─────▶ 보고서 단독 페이지
이슈 상세 ── 알림 본문 ────────────────▶ (같은 화면에서 펼침)
점검 구성 ── 설정 상태 항목 ───────────▶ (수정 제안 확인, 설정 반영은 사람이 파일에)
점검 상세 ── Phoenix 추적 열기 ↗ ──────▶ 외부 (설정이 있을 때만)
채팅 ── 답변의 점검·이슈·보고서 링크 ──▶ 아래 화면이 그 대상으로 이동
채팅 ── 답변의 [근거 N] ───────────────▶ 패널 안에서 원문 펼침 (서랍과 겹치지 않음)
```

사용자 흐름 F1~F6은 [정의서 §6.6](04-ui-spec.md#66-사용자-흐름)에 있다.

## 5. 공통 컴포넌트

공통 모양: 높이는 크기별(sm 20px · **md 24px 기본** · lg 32px). 이 문서 본문·표에 적은 이모지(🔴 🟠 🟡 ⚪ 🔍 ⚠️ ✅)는 §5.1 대응표의 아이콘 배지를 줄여 쓴 표기다. 실제 화면은 이모지가 아니라 선형 SVG 아이콘이다. Slack 메시지만 이모지를 쓴다.

### 5.1 축별 표시 (심각도 배지 + 보조 표시)

상태는 축마다 어휘가 하나다 ([정의서 §1.3](04-ui-spec.md#13-상태-어휘)). **한 배지 모양에 두 축의 뜻을 싣지 않는다.** 화면의 표시는 선형 SVG 아이콘 + 라벨이고, 아이콘만 쓰거나 라벨만 쓰는 표시는 없다.

**주 배지 — 심각도 (4종)**

| 항목 | 규격 |
|---|---|
| 높이 · 모서리 | 24px · 3px (각진 배지, 알약 아님) |
| 테두리 | 2px, 왼쪽만 6px. 색은 text 값 |
| 배경 · 글자 | soft 배경, text 색 글자·아이콘 (아이콘 16px, 라벨과 4px 간격, 가로 패딩 8px) |

| 이모지(자리 표시) | 배지 | 아이콘 (Lucide) | 색 | 쓰는 곳 |
|---|---|---|---|---|
| 🔴 | 긴급 | `octagon-alert` | 긴급 text/soft | 이슈 행, 이슈를 연·이어 간 점검 행, 상태 머리, 중요 문제, 상단 띠, 채팅 답변 |
| 🟠 | 주의 | `triangle-alert` | 주의 text/soft | 위와 같음 |
| 🟡 | 잠재 위험 | `circle-alert` | 잠재 위험 text/soft | 같음 (알림 없는 이슈) |
| ⚪ | 개선 권고 | `info` | 개선 권고 text/soft | 보고서의 "참고 — 개선 권고", 점검 구성 규칙 H01·H02 |

- 이슈가 없는 점검 행은 배지가 없다. 대신 muted 글자 `✓ 이상 없음`(작은 `circle-check` 아이콘, 정상 색은 아이콘에만)이다. 이슈가 아닌 점검 결과를 "이상" 같은 값으로 말하지 않는다.
- 개선 권고만 나온 점검도 이슈를 열지 않으므로 `✓ 이상 없음`으로 보이고, 행 끝에 muted 작은 숫자 `권고 2`만 붙는다.

**보조 표시 — 점검 상태·조사 상태·설정 상태**

작은 글자(13px)와 선형 아이콘만 쓴다. **배지 테두리·soft 배경·심각도 색(긴급·주의·잠재 위험·개선 권고)을 쓰지 않는다.** 색은 ink·muted·accent뿐이다.

| 축 | 값 | 표시 |
|---|---|---|
| 점검 상태 | 진행 중 | `loader` 아이콘 + `진행 중`, accent 글자 |
| | 완료 | 표시하지 않는다 (기본) |
| | 일부 확인하지 못함 | `ban` 아이콘 + `일부 확인하지 못함`, ink 글자 |
| | 중단 | `triangle-alert` 아이콘 + `중단`, ink 굵은 글자 |
| 조사 상태 | 조사 중 | `loader` 아이콘 + `조사 중`, accent 글자 (도구 호출 진행은 `4/8`을 붙인다) |
| | 완료 | 표시하지 않는다 |
| | 조사 미완(상한) | `triangle-alert` 아이콘 + `조사 미완`, ink 굵은 글자 |
| | 조사 실패 | `triangle-alert` 아이콘 + `조사 실패`, ink 굵은 글자 |
| 설정 상태 | 정상 | 한 줄 muted `설정 정상 · 마지막 확인 14:05` |
| | 확인 필요 | 상단 띠의 `설정 확인 필요 1` 칩 (§5.16) |

- 정상·복구 색(강청색)은 `circle-check` 아이콘에만 쓴다 (이상 없음, 해결, 복구 알림 보냄). 진행 중은 `--accent`다.
- 이슈 상태(열림·해결)는 §5.3의 별도 모양이다. 규칙 판정(적발·관찰 중·통과·확인하지 못함)은 §5.7의 칩이다.

### 5.2 1차 → 최종 심각도

심각도 값은 두 번 정해진다. 1차(규칙·게이트)는 긴급·주의·참고, 조사 뒤 **최종**은 보고서 영향 등급 4값이다 ([정의서 §1.3](04-ui-spec.md#13-상태-어휘)).

| 상황 | 표시 |
|---|---|
| 같음 | 최종 배지만 보인다 |
| 바뀜 | 최종 배지 오른쪽에 muted 13px로 `1차 🟠 주의 → 🔴 긴급`. 1차 이모지는 회색 글자와 함께 보이고 화살표 오른쪽이 현재 값이다. 1차가 `참고`이고 최종이 잠재 위험이면 `1차 참고 → 🟡 잠재 위험` |
| Service 수집 실패로 낮아짐 | `1차 🟠 주의 (Service 수집 실패로 낮춤)`. 낮춘 사유가 같은 줄에 붙는다 ([05-rules §0.3](05-rules.md#03-묶음용-데이터를-수집하지-못했을-때)) |
| 조사 전 | 1차 심각도만 보이고 보조 표시 `조사 중`이 옆에 붙는다 |

이슈 행에서는 배지 옆에, 상태 머리에서는 배지 아래 줄에 쓴다.

### 5.3 이슈 상태

| 상태 | 모양 |
|---|---|
| 열림 | **테두리만 있는 `OPEN` 배지**: 고정폭 대문자, 1px ink 테두리(반경 3px), 배경 없음 |
| 해결 | 테두리 없음, muted 글자 `✓ 해결 14:45` (해결 시각). 지속은 `14:05~14:45, 40분` |

### 5.4 확신도

`높음` `중간` `낮음` 글자와 3칸 점으로 보인다: `●●● 높음` / `●●○ 중간` / `●○○ 낮음`. 점 색은 ink(채움)·line(빈칸)이고 **상태색을 쓰지 않는다** (심각도와 헷갈리지 않게). 크기 13px, 점 지름 6px.

### 5.5 근거 칩

| 형태 | 모양 |
|---|---|
| `[근거 14]` | 고정폭 13px, `--accent` 글자, **1px accent 테두리 사각형**(반경 3px), 배경 surface, 높이 22px, 가로 패딩 6px. 호버에 `--accent-soft` 배경, 포커스에 윤곽 |
| `[근거 14, 15]` | 칩 하나 안에 번호 두 개. 번호마다 클릭 대상이 따로 있다 |
| `[근거 22~25]` | 칩 하나. 누르면 22번을 서랍에 열고, 서랍 헤더에 `22 · 23 · 24 · 25` 번호 알약이 나타나 서로 오갈 수 있다 |
| 문장 안 위치 | 문장 끝 마침표 앞, 앞 글자와 4px 띄운다 |
| 서랍이 열린 동안 | 열려 있는 칩은 accent로 채우고 글자는 surface |
| 존재하지 않는 번호 | 칩이 회색 점선 테두리로 보이고 누르면 서랍에 "근거를 찾을 수 없습니다" 빈 상태 |

### 5.6 추정 표기

문장 끝에 _(추정)_을 붙인다 (기울임, muted, 14px). 근거 칩이 있어야 할 자리에 칩이 없고 _(추정)_만 있다는 점이 눈에 띄어야 한다. 배경색은 두지 않는다.

### 5.7 규칙 판정 칩 (4종)

[05-rules §0.1](05-rules.md#01-판정-결과)의 판정 4가지다. 칩은 점검 상세의 "점검 판정" 절과 점검 구성의 규칙 표, 조사 과정의 게이트 단계에서 쓴다.

| 판정 | 모양 | 함께 보이는 값 |
|---|---|---|
| **적발** | 1차 심각도 배지(§5.1)에 `적발` 글자와 규칙 ID(고정폭). 예: 주의 배지 `⚠ 적발 W02`. 행 왼쪽에 심각도 막대 | 대상, 판정에 쓴 값 |
| **관찰 중** | **점선** 테두리 + 왼쪽 굵은 선, 글자 `관찰 중`. 옆에 `15분 중 10분째`와 가는 진행 막대(전체 폭 80px, 높이 4px, `--line` 바탕 위에 `--tip-dot` 채움) | 최초 관측 시각 |
| **통과** | 배지 없이 muted 글자 `✓ 통과` | 판정에 쓴 값 (예: `Endpoint Ready 3/3`) |
| **확인하지 못함** | 개선 권고 회색(`--tip`) 배지 `⊘ 확인하지 못함` | 못 읽은 kind와 사유 (예: `EndpointSlice — Kubernetes API 응답 없음`) |

### 5.8 버튼 3종 (지금 점검 버튼 3상태 포함)

`지금 점검` 버튼은 **GNB 오른쪽**에 있고 모든 화면에서 같은 자리다. 아래 `지금 점검`이 정식 라벨이다.

| 종류 | 모양 | 예 |
|---|---|---|
| 주 버튼 | accent 채움 + 흰 글자(6.10:1). 높이 32px, 반경 8px | `▶ 지금 점검` (`play` 아이콘) |
| 보조 버튼 | surface 배경 + accent 1px 테두리 + accent 글자 + 앞에 아이콘 | `링크 복사` (`copy` 아이콘) |
| 비활성 | `--surface-2` 배경 + muted 글자, 테두리 없음 | `점검이 진행 중입니다` |

| 지금 점검 버튼 상태 | 모양 | 동작 |
|---|---|---|
| 가능 | 주 버튼 `지금 점검` | 누르면 새 점검을 시작하고 그 점검 상세로 이동한다. 목록 맨 위에 새 행이 생기고 진행 표시가 붙는다 |
| 진행 중 | 비활성 `점검이 진행 중입니다`, 바로 아래(또는 툴팁)에 accent 링크 `진행 중인 점검 보기 ▸`. 주기 점검·Slack·CLI가 돌고 있어도 같다 (공유 잠금) | 누를 수 없다 |
| 쿨다운 | 비활성 `0:42 뒤 실행 가능`, 숫자는 tabular-nums로 1초마다 줄어든다. 툴팁에 "1분에 한 번만 실행할 수 있습니다" | 0:00이 되면 가능 상태로 돌아간다 |

- 직접 점검이 끝나 열린 이슈가 사라졌으면 **그 자리에서 이슈가 해결로 바뀌고** 복구 알림이 나간다 ([정의서 §6.5](04-ui-spec.md#65-점검-실행)). 화면에서는 새 점검 행이 `이상 없음 · 해결 #12`로 바뀌고, 상단 띠의 열린 이슈 수가 줄고, 이슈 상세의 타임라인에 복구 알림 항목이 붙는다. 해결 조건을 채우지 못한 점검(일부 확인하지 못함·중단)에서는 이 변화가 없다.
- 화면 실행의 결과는 화면에서만 보여주고 Slack으로 보내지 않는다 (복구 알림 예외).

### 5.9 접이식 단계 (타임라인)

조사 과정의 단계 목록이다. 세로선(1px `--line`)에 단계 점을 두고, 단계 제목 줄을 눌러 접고 편다.

| 상태 | 모양 |
|---|---|
| 접힘 | `▸ 단계 이름   요약 한 줄   시작 14:10:03 · 2s` |
| 펼침 | `▾` + 아래 들여쓴 본문 (도구 호출 행, 신호판 표 등) |
| 완료 | 점은 속이 찬 muted 색, 소요 시간 표시 |
| 현재 단계 (진행 중) | **현재 단계 카드** (아래) |
| 아직 안 한 단계 | 빈 점(테두리만), 글자 muted |
| 상한 도달·실패한 단계 | ink 테두리 점 + 삼각형 아이콘 + `조사 미완`·`조사 실패` 보조 표시 (§5.1) |

**현재 단계 카드**

| 요소 | 모양 |
|---|---|
| 행 | `--accent-soft` 배경. 왼쪽에 accent로 채운 원(라디오 모양) + 단계 이름 **도구 호출**(굵게). 오른쪽에 보조 표시 `조사 중` |
| 진행도 | 행 아래에 `4/8` (고정폭, 분모는 문제당 도구 호출 예산) + accent 진행 막대 (나머지는 `--line`) |
| 앞 단계 | 접혀 있고, 현재 단계 카드는 펼쳐져 있다 |

### 5.10 도구 호출 행

한 줄 구조: `도구이름(인자)  →  결과 요약   [근거 N]   (원문 ▸)`.

| 요소 | 모양 |
|---|---|
| 도구 이름·인자 | 고정폭 13.5px, ink. 인자는 muted |
| 결과 요약 | 본문 14px |
| 근거 | 근거 칩 (누르면 근거 서랍) |
| 원문 ▸ | accent 링크. 눌러 인자 전체와 요약 결과를 아래로 펼친다 (프롬프트·LLM 응답은 없다) |
| 상한에 걸려 못 한 호출 | 행은 없고 단계 아래에 `⚠ 상한 도달로 이후 호출 생략` 한 줄 (ink 글자 + `triangle-alert`) |

### 5.11 알림 이력 항목

이슈 상세의 타임라인과 보고서의 알림 이력에서 쓴다.

| 요소 | 모양 |
|---|---|
| 줄 | `14:05  최초 감지   [보냄]   메시지 본문 보기 ▾` 시각은 고정폭, 종류(최초 감지 · 원인 갱신 · 리마인더 · 복구) 굵게 |
| **보냄** 배지 | 정상 text/soft, `보냄` |
| **dry-run 기록** 배지 | 개선 권고 회색 text/soft, `dry-run 기록` (평가 중·Slack 승인 전에 기록만 한 메시지). 줄 전체를 muted로 둔다 |
| 본문 펼치기 | 펼치면 보낸 메시지 본문을 `--surface-2` 블록(고정폭 13.5px)으로 보인다. Slack 링크 자리는 `<점검 상세 링크>`·`<이슈 상세 링크>` 그대로 둔다 |
| 시간 순서 | 위가 오래된 것 (최초 감지부터) |

### 5.12 경고 배너

본문 맨 위(제목 바로 아래)에 한 줄 또는 두 줄로 붙는다. 폭 전체, 반경 8px, 패딩 12px 16px, 왼쪽 4px 막대. **점검·조사 상태는 보조 표시 규칙(§5.1)을 따라 심각도 색을 쓰지 않는다.**

| 배너 | 내용 | 모양 |
|---|---|---|
| 조사 미완 | `상한에 도달해 조사를 마치지 못했습니다 (도구 20/20). 확인하지 못한 가설은 "확인하지 못함"에 있습니다.` | `triangle-alert`, surface 배경, 1px ink 테두리 + 왼쪽 4px ink 막대 |
| 조사 실패 | `조사 중 오류가 발생했습니다: Azure OpenAI 응답 없음. 규칙·증상 결과만 표시합니다.` | 위와 같음 |
| 일부 확인하지 못함 | `일부 항목을 확인하지 못했습니다 (Kubernetes API 응답 없음). 확인한 결과만 표시합니다.` + 못 읽은 kind 목록 | `ban` 아이콘, `--tip-soft` 배경 |
| 결론 근거 없음 | 결론 바로 위: `결론이 인용한 근거 없음` | 위의 조사 미완 모양 |
| 점검 중단 | 점검 이력 목록 맨 위: `점검이 15분째 실행되지 않았습니다 (마지막 정상 점검 14:05)` | `triangle-alert`, 1px ink 테두리 |

### 5.13 빈 상태

| 위치 | 문구 | 이어지는 동작 |
|---|---|---|
| 점검 이력 기록 없음 | `점검 기록이 없습니다. 주기 점검은 5분마다 실행됩니다.` 보조: `상단의 지금 점검으로 바로 실행할 수 있습니다.` | GNB 버튼 |
| 열린 이슈 없음 | 상단 띠 자리에 muted 한 줄 `열린 이슈 없음` | — |
| 목록 필터 결과 없음 | `조건에 맞는 점검이 없습니다.` (이슈는 `조건에 맞는 이슈가 없습니다.`) | `필터 지우기` 링크 |
| 이슈 없음 | `이슈 기록이 없습니다. 장애 신호나 증상이 감지되면 여기에 쌓입니다.` | — |
| 채팅 비어 있음 | `저장된 이력에 대해 질문해 보세요.` 아래에 예시 질문 칩 3개 | 칩을 누르면 질문이 입력창에 채워져 전송된다 |
| 근거 없음 | `근거를 찾을 수 없습니다.` | 서랍 닫기 |
| 알림 이력 없음 | `보낸 알림이 없습니다 (잠재 위험·개선 권고는 알림 없이 화면에만 표시됩니다).` | — |

빈 상태는 중앙 정렬 아이콘 없이 muted 글자 두 줄과 링크 하나로만 보인다 (그림·일러스트 없음).

### 5.14 마스킹 표시

마스킹된 값은 `****`로 보이고 고정폭이다. 키 이름(`password`, `Authorization` 등)은 보이고 값만 가려진다. 배경 강조나 자물쇠 아이콘은 쓰지 않는다. 근거 원문과 알림 본문 모두 같다.

```text
LLM_API_KEY=****
```

### 5.16 상단 띠

| 요소 | 모양 |
|---|---|
| 열린 이슈 | 라벨 `열린 이슈`(muted 13px) 뒤에 심각도별 작은 배지 sm: `긴급 1` `주의 0` `잠재 위험 0`. 0건인 심각도는 배지 대신 muted 글자 `주의 0`(테두리·색 없음). **누르면 이슈 목록이 그 심각도 + 열림 필터로 열린다.** 열린 이슈가 전혀 없으면 muted 한 줄 `열린 이슈 없음` |
| 설정 확인 필요 | 오른쪽 끝 칩: 1px ink 테두리, ink 글자, 앞에 `triangle-alert`, `설정 확인 필요 1`. **누르면 점검 구성의 설정 상태 절**(`#health`)로 간다. 설정이 정상이면 칩을 그리지 않는다 |

- 개선 권고만 있고 열린 이슈가 아닌 상태는 이 띠에 올리지 않는다 (이슈가 아니다).

### 5.17 필터 막대

점검 이력과 이슈 목록 맨 위에 붙는다 (스크롤해도 고정). 필터는 주소 쿼리에 남아 돌아와도 유지된다.

| 요소 | 모양 |
|---|---|
| 줄 1 | 검색 입력(왼쪽, `search` 아이콘, 높이 32px, 반경 6px): 서비스 이름·규칙 ID·이슈 제목·실패한 기능. 오른쪽에 `필터 지우기` 링크(필터가 있을 때만) |
| 줄 2 | 필터 알약: 높이 28px, 반경 999px, 1px `--line` 테두리, 14px. 값을 고르면 알약 안에 값이 보이고(`심각도: 긴급 외 1`) 선택된 알약은 accent 윤곽 + ink 굵게(채움 없음). 눌러 여는 목록은 체크박스 메뉴(복수 선택). 건수는 쓰지 않는다 |
| 점검 이력의 필터 | **기간**(최근 1시간 · 오늘 · 7일 · 직접 지정) · **심각도**(긴급 · 주의 · 잠재 위험 · 개선 권고 · 이상 없음) · **이슈 관계**(열림 · 이어짐 · 해결) · **실행 방식**(주기 · 직접(화면) · Slack · CLI) · **점검 상태**(일부 확인하지 못함 · 중단) |
| 이슈 목록의 필터 | **상태**(열림 · 해결) · **심각도** · **기간** |
| 줄 넘침 | 알약이 넘치면 줄바꿈한다. 좁은 폭에서는 `필터` 버튼 하나(`sliders-horizontal`)로 접고 누르면 같은 알약이 펼쳐진다 |

### 5.18 점검 행

목록 폭 420px에 맞춘 **두 줄 행**이다. 최소 높이 56px.

```text
┃14:05  [긴급] 1차 긴급   이슈 열림 #12                 ← 줄 1: 시각 · 심각도 배지 · 이슈 관계
┃      채팅 실패 · 증상 chat 2단계          주기 · 조사 중  ← 줄 2: 요약(muted) · 실행 방식 · 보조 상태
```

| 요소 | 모양 |
|---|---|
| 왼쪽 막대 | 이슈를 열었거나 이어 간 점검은 4px 심각도 막대(dot 색). 이상 없음 행은 막대 없음 |
| 줄 1 | 시각(고정폭) · 심각도 배지(없으면 `✓ 이상 없음`) · 오른쪽 끝 **이슈 관계** |
| 이슈 관계 | 고정폭 작은 글자, 4종 중 하나: `이슈 열림 #12` · `이어짐 #12` · `해결 #12` · (관계없음이면 아무것도 쓰지 않음). 여러 이슈와 얽히면 가장 높은 심각도의 이슈를 보이고 `+2`를 붙인다. `해결`은 정상 색 `circle-check` 아이콘이 앞에 붙는다 |
| 줄 2 | 요약(실패한 기능 또는 주요 신호, 13px muted, 한 줄 말줄임) · 실행 방식(`주기` `직접` `Slack` `CLI`, 고정폭 알약, 회색) · 보조 표시(§5.1, 해당할 때만) · 개선 권고만 있으면 `권고 6`(muted) |
| 선택 | 선택된 행은 `--accent-soft` 배경 + 1px accent 윤곽. 심각도 막대는 그대로 |
| 정상 접기 | 연속된 `이상 없음` 행(보조 표시가 `일부 확인하지 못함`인 행과 이슈 관계가 있는 행은 제외, 판단)은 한 줄 `✓ 이상 없음 12회 · 13:00~14:00`으로 접는다. muted 글자, 높이 36px, 오른쪽 `펼치기 ▸`. 펼치면 행이 나열되고 `접기 ▴`가 생긴다 |
| 점검 중단 구간 | 행 사이에 점선 구분 행: `점검 중단 13:25~13:55 (점검이 실행되지 않음)` + `triangle-alert`. 상단의 점검 중단 배너(§5.12)와 같은 규칙으로 ink 1px 점선 테두리 |
| 줄 높이 | 44px 이상 터치 대상 |

- 이상 없음 행의 규칙별 판정은 상세에서 본다. 목록에는 올리지 않는다.
- 필터 중에는 접기를 쓰지 않고 해당 행만 나열한다.

### 5.19 이슈 행

| 요소 | 모양 |
|---|---|
| 열림 | 왼쪽 4px 심각도 막대. 줄 1: 심각도 배지 · `#12` 고정폭 · 오른쪽 끝 `OPEN` 배지 (§5.3). 줄 2: 제목(15px 600, 한 줄 말줄임). 줄 3(muted 13px): `최초 감지 14:05 · 지속 35분 · 리마인더 1/3 · 보고서 1` |

### 5.22 질문 버튼 · 맥락 칩

| 요소 | 모양 |
|---|---|
| GNB `질문` | 보조 버튼: 1px `--line` 테두리, `--surface` 배경, ink 글자, 앞에 `message-circle-question` 아이콘(16px, ink). 높이 32px. 패널이 열려 있으면 `--surface-2` 배경(눌린 모양) |
| 맥락 칩 | 패널 헤더 아래 알약(`--surface-2`, 반경 999px, 고정폭 13px) 한 줄 가로 배치: 선택한 이슈 `이슈 #12 ✕` · 선택한 점검 `점검 14:05 ✕` · 이력 필터 `필터: 오늘 · 긴급 ✕`. ✕로 하나씩 뺀다. 아무 맥락이 없으면 알약 하나 `전체 이력`(✕ 없음, muted) |

- 반짝이·그라데이션·색 배경·애니메이션을 쓰지 않는다. 오른쪽 아래에 떠 있는 버튼으로 만들지 않는다 (GNB에만 있다).
- accent 색은 쓰지 않는다 (accent 청록은 `지금 점검`·링크·근거 칩에 쓴다. 질문은 무채색).

## 6. 페이지별 화면

> 와이어프레임의 이모지는 자리 표시이고, 실제 화면에서는 §5.1의 SVG 아이콘 배지다. 페이지 구성의 정본은 [정의서 §6.4](04-ui-spec.md#64-페이지-구성)다. 레일·GNB·상단 띠(§4.1)는 모든 와이어프레임에서 생략했다.

### 6.1 점검 이력 (홈) — `/p/{p}/checks`

**목적**: 열어서 바로 "지금 괜찮은가, 최근 무슨 일이 있었나"를 본다. 점검을 시간순으로 훑고, 이슈를 열었거나 이어 간 행을 눌러 상세로 간다. 목록-상세 분할이라 상세를 열어도 목록·필터·스크롤이 그대로다.

```text
┌ 필터 막대 ────────────────────────┬ 점검 상세 (선택했을 때) ────────────────────────┐
│ [검색: 서비스·규칙·이슈 제목      ] │ dev › 점검 이력 › 10/26 14:05                     │
│ [기간: 오늘][심각도][이슈 관계]     │ 점검 10/26 14:05                                 │
│ [실행 방식][점검 상태]  필터 지우기 │ 조치 · 판정 · 조사 · 근거                          │
├───────────────────────────────────┤ ① 상태 머리  🔴 긴급 (1차 🔴) · 이슈 #12 열림 …   │
│ [점검 중단 배너 — 중단 중일 때만]   │ …                                                │
│ 15:10 🔍 점검 중                    │                                                  │
│       화면 점검 · 진행 중           │                                                  │
│ ✓ 이상 없음 4회 · 14:50~15:05  ▸   │                                                  │
│ 14:45 ✓ 이상 없음      해결 #12     │                                                  │
│       주기 · 권고 2                 │                                                  │
│┃14:40 🔴 긴급           이어짐 #12  │                                                  │
│┃      채팅 실패                주기 │                                                  │
│┃14:35 🔴 긴급           이어짐 #12  │                                                  │
│┃14:05 🔴 긴급     이슈 열림 #12     │                                                  │
│┃      채팅 실패 · 증상 chat 2단계 … │                                                  │
│ ✓ 이상 없음 2회 · 13:55~14:00  ▸   │                                                  │
│ ⚠ 점검 중단 13:25~13:55            │                                                  │
└───────────────────────────────────┴──────────────────────────────────────────────────┘
```

| 영역 | 표시 항목 | 디자인 지침 |
|---|---|---|
| 제목 | 목록 위 페이지 제목 `점검 이력`(24px)과 muted 13px `주기 점검은 5분마다` | `지금 점검`은 이 제목 줄이 아니라 GNB에 있다 |
| 필터 막대 | §5.17 (기간 · 심각도 · 이슈 관계 · 실행 방식 · 점검 상태 · 검색어) | 주소 쿼리에 남는다 |
| 점검 중단 배너 | 중단 중일 때만, 목록 맨 위 (§5.12) | |
| 점검 행 | 시각 · 심각도 배지 또는 `✓ 이상 없음` · 이슈 관계 · 요약 · 실행 방식 · 보조 표시 (§5.18) | 주 분류는 이슈 심각도. 점검 상태는 보조 표시로만 |
| 정상 접기 | 연속된 이상 없음은 한 줄로 접힘 (하루 288행 방지). 개선 권고만 나온 점검도 이상 없음으로 접고 `권고 n`만 붙는다 | §5.18 |
| 점검 중단 구간 | 점검이 실행되지 않은 구간을 행으로 표시 | §5.18 |
| 행을 눌렀을 때 | 오른쪽에 점검 상세(§6.2)가 열린다. 주소가 `/p/{p}/checks/{run}`으로 바뀐다 | 선택 행 강조, 목록 스크롤 유지 |
| 열린 이슈 | 이 페이지에 별도 띠를 만들지 않는다. 상단 띠(§5.16)가 맡는다 | |

**그려야 할 상태**

| 상태 | 내용 |
|---|---|
| **열린 이슈 있음** (14:40 기준) | 위 와이어프레임. 상단 띠 `열린 이슈 긴급 1`, GNB `마지막 점검 14:40`. 이슈 열림·이어짐 행에 심각도 막대와 배지 |
| **모두 정상** (15:05 기준) | 상단 띠 `열린 이슈 없음`. 최근 행은 `✓ 이상 없음 · 해결 #12`와 접힌 이상 없음 행들 |
| **점검 중단** (13:40 기준) | 목록 맨 위 중단 배너, GNB 점검 시각 줄이 `점검 15분째 안 됨 …`, 중단 구간 행. 상단 띠는 그대로 |
| **진행 중** (15:10 기준) | 목록 맨 위 행 `15:10 점검 중 · 직접 · 진행 중`, GNB `지금 점검` 비활성, 상세에 진행 표시 |
| **일부 확인하지 못함** (09:55 기준) | `✓ 이상 없음` + 보조 표시 `일부 확인하지 못함`. 접지 않는다 |
| **기록 없음** | 목록 자리에 빈 상태 (§5.13), 상세 패널 비어 있음 |
| 필터 | 필터 중에는 접기 없이 해당 행만 나열. 결과 없음 빈 상태 |
| 좁은 화면 | 목록만 전체 폭, 행을 누르면 상세가 전체 화면 (§4.6) |

### 6.2 점검 상세 — `/p/{p}/checks/{run}`

**목적**: 한 점검에서 무엇이 판정됐고, 조사가 어디까지 왔고, 결론이 무엇인지를 위에서 아래로 한 번에 읽는다. 가장 많이 보고 가장 공들여 그린다. 맨 위는 지금 알아야 할 것, 그 아래는 점검이 진행된 순서다.

```text
dev › 점검 이력 › 10/26 14:05
점검 10/26 14:05
조치 · 판정 · 조사 · 근거

① 상태 머리
  🔴 긴급   (1차 🔴 긴급)  ●●● 높음   이슈 #12 [OPEN]   ← 이슈 칩을 누르면 이슈 상세
  10/26 14:05 · 주기 점검 · 완료 48초
  llm-gateway가 429를 반환해 gateway가 502로 응답하고 있습니다. [근거 14, 15]    ← 결론 한 줄

② 권장 조치 (자동 실행하지 않음)    1. … 2. …   (명령은 고정폭 블록 + 복사)
  재검증 방법 …

③ 점검 판정
  적발 / 관찰 중 / 확인하지 못함인 규칙과 실패한 증상만 펼침
  ✗ 증상 chat  실패 (login 성공, chat 2단계 실패)  [근거 11]
  통과 13건 ▸ (접힘)        게이트: 경로 B · 1차 심각도 긴급 · 문제 지문 새로 생성

④ 조사
  [조사 보고서] 채팅 실패 — llm-gateway 할당량 소진                (보고서 R-0412)
  ■ 문제 (최대 3건, rank 순)
  ■ 근거   사전 확인 / 가설 검증
  ■ 가설 판정
  ■ 확인한 범위
  ■ 참고 — 개선 권고
  조사 48초 · 도구 호출 9회 · 2.1만 토큰 · 참고한 지침 app-layer-failure.md
  조사 과정 보기 ▸  (접힘 — §6.3)

⑤ 근거
  본문의 [근거 N] → 오른쪽 서랍.  이 점검의 근거 전체 목록 ▸ (맨 아래, 접힘)
```

| 영역 | 표시 항목 | 디자인 지침 |
|---|---|---|
| 제목·빵부스러기 | 빵부스러기 + 제목 `점검 10/26 14:05`(24px). 진행 중인 점검은 제목 오른쪽에 보조 표시 `진행 중` | |
| ① 상태 머리 | 최종 심각도 배지 lg(1차와 다르면 `1차 … → …` 표시, §5.2) · 확신도 · **이슈 칩**(`이슈 #12`, 고정폭 accent 링크, 열림이면 `OPEN` 배지 함께) · 시각 · 실행 방식 · 점검 상태 · 소요 시간. 아래에 결론 한 줄(15px 500). 조사 중이면 결론 자리에 `조사 중: 도구 호출 4/8`(문제당 예산), 이상 없음이면 `✓ 이상 없음` | 이슈가 없으면 배지·이슈 칩 없음. 이슈 관계(열림·이어짐·해결)는 muted로 칩 옆에 쓴다 |
| 경고 배너 | 조사 미완 · 조사 실패 · 일부 확인하지 못함 · 결론 근거 없음 (§5.12) | 해당할 때만 ① 바로 아래. `conclusion_supported=false`면 결론 바로 위에 `결론이 인용한 근거 없음`, 결론 끝에 _(추정)_ |
| ② 권장 조치 | 번호 목록. 명령은 `--surface-2` 고정폭 블록, 오른쪽에 `복사` 버튼. 아래에 재검증 방법 한두 줄 | **조사가 끝났을 때만** 나온다. "자동 실행하지 않음"을 제목 옆 muted로 항상 표시 |
| ③ 점검 판정 | 규칙 판정 칩 (§5.7): 적발 · 관찰 중 · 확인하지 못함은 펼쳐 보이고(통과 위), 실패한 증상(API 시나리오 단계별 성공·실패)도 같다. **통과 n건은 한 줄로 접는다.** 게이트 경로(A·B·C)와 이유 한 줄 | 통과는 muted. 적발·관찰 중·확인하지 못함이 없고 증상도 정상이면 통과 요약만 보인다 |
| ④ 조사 | 진행 중: 단계 목록이 펼쳐져 갱신된다 (§6.3 방식). 끝남: 보고서 본문 | 아래 보고서 본문 표 |
| ⑤ 근거 | 본문의 `[근거 N]`은 서랍으로 연다. 이 점검의 근거 전체 목록은 맨 아래에 접혀 있다(번호 · 종류 · 대상) | |

**보고서 본문 (④, 보고서 단독 페이지와 같은 구성)**

| 영역 | 표시 항목 | 디자인 지침 |
|---|---|---|
| 보고서 제목 | `[조사 보고서]` 접두(muted) + 제목(20px 600) + 보고서 ID `R-0412`(고정폭 muted) | 제목 앞에 보조 표시 `조사 미완`·`조사 실패`가 붙을 수 있다 |
| 문제 | `Report.issues`(선별 항목, 최대 3건)를 rank 순 목록으로. 항목: rank 숫자 · 심각도 배지 · 제목 · 확신도 · 근거 칩 | 1건이어도 목록 형태. Slack M1·M6과 같은 순위. 이슈(`#12`)와 구별되게 절 이름은 `문제`다 |
| 근거 | 두 묶음: **사전 확인**(`preliminary_facts`)과 **가설 검증**. 묶음 이름은 muted 14px 굵게, 사실은 점 목록, 문장 끝에 근거 칩 | 사전 확인의 사실은 항상 칩이 있다. 칩이 없으면 안 된다 (`Fact`는 근거 1개 이상) |
| 가설 판정 | 표: 가설(①②③) · 판정(**지지** / **배제** / **판단 보류**) · 이유 · 근거 칩 | 판정은 글자 + 기호(✓ 지지, ✕ 배제, ? 판단 보류). 색은 쓰지 않는다 (지지가 "좋은 것"이 아니라서) |
| 확인한 범위 | 두 열: **확인함**(`✓`), **확인하지 못함**(`⊘`) | 구동·설정·연결·로그 네 영역 각각. 확인하지 못함 칸은 `--tip-soft` 배경 |
| 참고 — 개선 권고 | 규칙 ID(H01·H02) · 한 줄 설명 · 대상 서비스 수. ⚪ 배지 | 섹션 전체를 muted로 줄이고 기본은 펼침. 지금 장애와 무관 |
| 푸터 | `조사 48초 · 도구 호출 9회 · 2.1만 토큰 · 참고한 지침 …` (13px muted) + `조사 과정 보기 ▸` | |

보고서 본문의 **알림 이력**은 보고서가 아니라 이슈에 딸린 기록이라 이슈 상세의 타임라인에서 본다 (§6.4).

**그려야 할 상태**

| 상태 | 달라지는 점 |
|---|---|
| 조사 진행 중 (Slack 1차 알림 직후) | ① 진행 표시 `조사 중: 도구 호출 4/8`, ② 없음, ③ 판정, ④ 단계 목록(2초마다 갱신, §6.3). 보고서는 아직 없다 |
| 조사 끝남 (정상 완료) | 위 와이어프레임. ③은 적발 항목만 펼침 (R-0412, §7.4) |
| 조사 미완 | 배너 `조사 미완`, "확인하지 못함"에 남은 가설, 가설 판정에 `판단 보류`, 확신도 낮춤 |
| 조사 실패 (규칙·증상 결과만) | 배너 `조사 실패`. ②④의 근거·가설 판정·권장 조치는 `조사가 끝나지 않아 없음` muted 한 줄. 대신 ③의 **규칙·증상 결과**(적발된 규칙, 실패한 증상 단계)가 상세 표로 보인다. 문제는 규칙 결과 기준 1건 |
| 결론 근거 없음 | 결론 위 `결론이 인용한 근거 없음` 배너와 결론 끝 _(추정)_ |
| 심각도 변경 | ① 배지 아래 `1차 🟠 주의 → 🔴 긴급`. 예시는 §7.5 |
| 일부 확인하지 못함 | 배너 + ③에 `⊘ 확인하지 못함` 칩과 kind·사유 |
| 이슈 이어짐 (14:35 점검) | ① 배지 + `이어짐 #12`. 같은 문제라 AI 조사는 생략됐고 ④는 `같은 이슈의 보고서 R-0412 사용` 링크 한 줄 |
| 이슈 해결 (14:45 점검) | ① `✓ 이상 없음`, 이슈 칩 `#12 ✓ 해결 14:45`. ③ 통과 요약, ②④ 없음 |
| 이상 없음 | ① `✓ 이상 없음`, ③ 통과 요약(접힘), ②④ 없음 |
| 중단된 점검 | ① 보조 표시 `중단`, ③에 수집하지 못한 범위 |

### 6.3 조사 과정 (점검 상세 ④의 "조사 과정 보기")

**목적**: 에이전트가 무엇을 했는지 전부 보이게 한다. 운영자는 결론을 믿어도 되는지 확인할 때, 개발자는 에이전트를 디버깅할 때 쓴다. 별도 페이지가 아니라 점검 상세 ④ 안에서 접고 펴는 영역이다. 진행 중일 때는 처음부터 펼쳐져 있다.

```text
조사 과정 — 10/26 14:05 점검 (주기)                       조사 중 / (완료면 표시 없음)
에이전트 investigator:v1 · 모델 gpt-6.1-sol · 도구 9/20 · 48s/150s · 21k tokens
──────────────────────────────────────────────────────────────────────────────

 │

 │

 │     신호판    agent 0 · llm-gateway 0 · gateway 0   (서비스별 묶음)
```

| 영역 | 표시 항목 | 디자인 지침 |
|---|---|---|
| 제목 줄 | `조사 과정 — 10/26 14:05 점검 (주기)` + 조사 상태 보조 표시 (§5.1) | |
| 머리말 | `에이전트 <이름>:<버전> · 모델 · 도구 N/20 · N초/150초 · N k tokens` (상한은 `core/guard/budget.py`의 값) | 한 줄, 고정폭 알약처럼 보이게 `--surface-2` 배경, 13px. 상한에 가까우면(예: 도구 18/20) 숫자만 ink 굵게 |
| 단계 목록 | §5.9의 접이식 단계 8개: 규칙 → 증상 → 게이트 → 사전 확인 → 계획 → 도구 호출 → 가설 판정 → 보고서·검증 | |

| 도구 호출 단계 | §5.10의 행 목록 | |
| 가설 판정 | `① 배제 · ② 지지 · ③ 배제` 요약, 펼치면 보고서와 같은 표 | |
| 보고서·검증 | `근거 검증 통과 · 추정 0문장 → 보고서 R-0412` (링크) | |
| 하단 | `Phoenix 추적 열기 ↗` (외부 링크 아이콘, accent 링크) — **설정이 있을 때만** | 프롬프트·LLM 응답 원문은 이 화면에 없다 |

**그려야 할 상태**

| 상태 | 내용 |
|---|---|
| 진행 중 | 위 와이어프레임. **수 초마다 단계 목록만 갱신** (`GET /p/{p}/checks/{run}/steps` 조각, 페이지가 깜빡이지 않게 변경된 줄만 바뀐다). 현재 단계는 §5.9의 현재 단계 카드. 앞 단계는 접혀 있고 현재 단계는 펼쳐져 있다. 머리말 숫자도 함께 갱신. 같은 시각 상태 머리는 `조사 중: 도구 호출 4/8` |
| 완료 | 모든 점이 속이 찬 muted 색, 마지막 단계에 보고서 링크, 머리말 소요 시간 확정. 접힌 채로 보인다 |
| 상한 도달 | 보조 표시 `조사 미완`, 머리말의 `도구 20/20` 또는 `150s/150s`가 ink 굵게, 도구 호출 단계 아래 `상한 도달로 이후 호출 생략`, 가설 판정에 판단 보류, 보고서·검증 단계는 `조사 미완으로 저장` |
| AI 호출 없음 (경로 C) | 단계가 규칙·증상·게이트 3개만 있고 `AI 조사 없음 — 규칙·증상 모두 정상` 한 줄. 에이전트 머리말은 없다 |
| 조사 실패 | 현재 단계에 `조사 실패: Azure OpenAI 응답 없음`, 이후 단계는 빈 점 |

### 6.4 이슈 — `/p/{p}/issues`, `/p/{p}/issues/{id}`

**목적**: "이 장애가 언제 시작해 지금 어떤 상태이고, 무슨 알림이 나갔나"를 이슈 하나로 돌아본다. 열린 이슈를 먼저 보고, 해결된 이슈를 되짚는다. 리마인더·복구 알림의 링크가 상세로 온다.

```text
┌ 필터 막대 ────────────────────────┬ 이슈 상세 ──────────────────────────────────────┐
│ [상태: 열림 외 1][심각도][기간]    │ dev › 이슈 › #12                                  │
│                                   │ 이슈 #12                                         │
├───────────────────────────────────┤ 결론 · 타임라인 · 보고서                          │
│┃🔴 긴급  #12             [OPEN]   │ ① 🔴 긴급 (1차 🟠 주의)  [OPEN]                    │
│┃채팅 실패 — llm-gateway 할당량…   │    채팅 실패 — llm-gateway 할당량 소진             │
│┃최초 14:05 · 지속 35분 · 리마인더 1/3│    영향: 채팅·보도자료 초안 생성 전체              │
│ ──────── 해결됨 ────────          │    최초 감지 14:05 · 지속 35분                     │
│ 🟠 주의  #11        ✓ 해결 12:05   │ ② 지금 결론  (최신 보고서 R-0412)                  │
│  신규 배포가 뜨지 않음 — …         │    llm-gateway가 429를 반환 … [근거 14, 15]       │
│  11:25~12:05, 40분 · 보고서 1      │    조치 · 재검증 방법                              │
│ 🔴 긴급  #10        ✓ 해결 09:25   │ ③ 타임라인 (시각순)                                │
│  agent 관련 기능 전부 실패 — …     │    14:05 점검 · 이슈 열림                          │
│  09:05~09:25, 20분 · 보고서 1      │    14:05 Slack 1차 알림 [보냄] ▾                  │
│                                   │    14:12 조사 완료 · 원인 갱신 알림 [보냄] ▾       │
│                                   │    이어짐 5회 · 14:10~14:30 ▸                     │
│                                   │    14:35 리마인더 [보냄] ▾                         │
│                                   │ ④ 보고서                                         │
│                                   │    R-0412 채팅 실패 — … (14:12)                   │
└───────────────────────────────────┴──────────────────────────────────────────────────┘
```

| 영역 | 표시 항목 | 디자인 지침 |
|---|---|---|
| 목록 | 이슈 행 (§5.19). 필터: 상태 · 심각도 · 기간 (§5.17). 열림이 위, 그 아래 `해결됨` 구분선 + 해결 | 열린 이슈가 없으면 열림 영역에 muted 한 줄 |
| ① 상태 머리 | 심각도 배지 lg(1차 → 최종, §5.2) · 상태 `OPEN` 또는 `✓ 해결 14:45` · 제목(최신 보고서 1순위 문제, 없으면 실패한 기능·주요 신호) · 영향 기능 · 최초 감지 · 지속 (해결이면 `14:05~14:45, 40분`) | 조사 중이면 보조 표시 `조사 중` |
| ② 지금 결론 | 최신 보고서의 결론 한 줄 + 권장 조치·재검증 방법. 조사 중이면 진행 표시 | 조치 명령은 고정폭 블록 + 복사 |
| ③ 타임라인 | §5.20. 이슈를 연 점검 → 1차 알림(보낸 본문 펼침) → 조사 완료·원인 갱신 알림 → 리마인더 → (지문 변경·재조사) → 해결한 점검 → 복구 알림. 사이의 이어짐 점검은 `이어짐 n회`로 접힘. 점검 항목은 점검 상세로 간다 | 알림은 실제로 보낸 메시지와 dry-run 기록을 모두 보인다 (`dry-run 기록` 배지, §5.11) |
| ④ 보고서 | 이 이슈에서 나온 보고서 목록 (지문이 바뀌어 재조사했으면 여러 개, 최신이 위). 행: `R-0412` · 제목 · 시각 · 심각도 · 확신도 → 보고서 단독 페이지 | |
| 해결된 이슈 | 같은 구성. ① 상태가 `✓ 해결 14:45`로 바뀌고 타임라인 끝에 해결한 점검과 복구 알림 | |

**그려야 할 상태**

| 상태 | 내용 |
|---|---|
| 열림 (#12, 14:40 기준) | 위 와이어프레임 |
| 해결 (#12, 15:05 기준) | ① `✓ 해결 14:05~14:45, 40분`, ③ 끝에 `14:45 점검 · 해결` + `복구 알림 [보냄]` |
| 직접 점검으로 해결 | 해결한 점검 항목에 실행 방식 `직접`, 복구 알림이 그 시각에 바로 붙는다. 주기 점검을 기다린 간격이 없다 (§7.7) |
| 1차 → 최종 심각도 변경 | ① 배지 옆 `1차 🟠 주의 → 🔴 긴급` |
| 지문 변경·재조사 | ③에 `문제 지문 변경 · 재조사` 항목, ④에 보고서가 둘 |
| 조사 중 | ① 보조 표시, ② `조사 중` 진행 표시, ③ 1차 알림 항목까지, ④ 비어 있음 |
| dry-run 알림 | 알림 항목이 `dry-run 기록` 배지, 줄 muted |
| 이슈 없음 | 빈 상태 (§5.13) |

### 6.5 보고서 단독 페이지 — `/p/{p}/reports/{id}`

**목적**: 보고서 하나를 공유용 주소로 읽는다. 점검 상세의 ①②④와 같은 구성이다.

```text
dev › 이슈 › #12 › 보고서 R-0412
조사 보고서 R-0412
① 상태 머리   🔴 긴급 · ●●● 높음 · 이슈 #12 [OPEN] · 14:05 점검 · 조사 48초
② 권장 조치
④ 조사        ■ 문제 · ■ 근거 · ■ 가설 판정 · ■ 확인한 범위 · ■ 참고 — 개선 권고
              조사 과정 보기 ▸
```

- 목록 없이 본문 폭 840px 가운데 한 열이다 (§4.3). 레일·GNB·상단 띠는 그대로 있다.
- 빵부스러기는 이슈에서 왔으면 `이슈 › #12 › 보고서 R-0412`, 점검에서 왔으면 `점검 이력 › … › 보고서 R-0412`.
- 그려야 할 상태는 점검 상세의 조사 끝남·조사 미완·조사 실패·결론 근거 없음·심각도 변경과 같다.

### 6.6 점검 구성 — `/p/{p}/setup`

**목적**: "KubeGuardian이 무엇을 점검하고, 그 점검을 믿을 수 있나"에 답한다. 목록-상세 분할이 아니라 한 열 페이지다 (본문 최대 폭 960px). 화면에서 설정을 바꾸지 않는다.

```text
점검 구성
설정 상태 · 규칙 · 증상 시나리오 · 대상 설정                    ← 절 바로가기

① 설정 상태 (#health)
  ┃⚠ 시나리오 chat — 대상 API 문서에 없는 경로를 호출                      ← 확인 필요 항목
  ┃  14:05부터 · 증상 감지 chat이 '확인하지 못함'
  ┃  수정 제안   설정   POST /v1/chat
  ┃              문서   POST /api/v1/chat
② 규칙   (14개 · 장애 신호 12 · 개선 권고 2)
  ID   이름                  무엇을 보나        지속   구분      1차 심각도   마지막 점검 결과
  S01  selector에 맞는 Pod 없음 …             즉시   장애 신호  긴급        적발 0 · 관찰 중 0
  W02  롤아웃 정체             …              15분   장애 신호  주의        적발 0 · 관찰 중 2
  …
③ 증상 시나리오
  chat   채팅                  login → chat    ⊘ 확인하지 못함
④ 대상 설정  (읽기 전용 · 원본은 kubeguardian.yaml)
  core_paths: …   required_config: …
```

| 영역 | 표시 항목 | 디자인 지침 |
|---|---|---|
| ① 설정 상태 | 확인 필요 항목이 있으면 맨 위에: 무엇이(시나리오·API·대상 서비스) · 언제부터 · 어떤 점검이 `확인하지 못함`이 되는지 · 수정 제안(대상 API 문서와 비교) (§5.21). 정상이면 한 줄 `설정 정상 · 마지막 확인 14:05` | `#health` 주소로 바로 이 절에 온다. Slack M10과 상단 띠 `설정 확인 필요`가 여기로 링크한다 |
| ② 규칙 | 점검 지도 단계 순서의 표 (§5.21) | 판정에 쓰는 규칙의 세부는 05-rules가 정본이라 여기서 펼치지 않는다 |
| ③ 증상 시나리오 | 이름 · 지키는 기능 · 단계 · 마지막 결과 | 확인하지 못함은 §5.1 보조 표시 |
| ④ 대상 설정 | 핵심 경로(`core_paths`), 선언한 필수 설정(`required_config`)을 읽기 전용 블록으로 | 편집 컨트롤 없음. 수정은 사람이 설정 파일에 반영한다 |

**그려야 할 상태**: 설정 확인 필요(위 와이어프레임, 항목 1건) · 설정 정상(① 한 줄만) · 확인 필요 항목이 여러 건(카드가 세로로 쌓임).

### 6.7 근거 서랍 — `?ev=N`

**목적**: 보고서의 문장이 실제 수집한 데이터에서 나왔는지 원문으로 확인한다. 보던 화면을 떠나지 않는다.

```text
┌────────────────────────────────────────────┐
│ [근거 14]  log_excerpt                  ✕  │
│ 22 · 23 · 24 · 25   ← 범위·복수 칩에서 열 때만 │
├────────────────────────────────────────────┤
│ 대상      dev/Pod/agent-7c9f-x2k           │
│ 수집 시각 14:07:12                          │
│ 출처      GET /api/v1/namespaces/dev/pods/ │
│           agent-7c9f-x2k/log               │
│ ┌────────────────────────────────────────┐ │
│ │ 14:06:58 WARN llm-gateway returned 429 │ │
│ │ Too Many Requests (insufficient_quota) │ │
│ │ Authorization: Bearer ****             │ │
│ └────────────────────────────────────────┘ │
│ 단독 페이지 링크 복사 ⧉                     │
└────────────────────────────────────────────┘
```

| 영역 | 표시 항목 | 디자인 지침 |
|---|---|---|
| 헤더 | `[근거 N]` (칩 모양, 크게), 종류 알약(`resource` · `event` · `log_excerpt` · `probe_result` · `app_api` · `detector`, 고정폭), 닫기 ✕ | 헤더는 서랍 안에서 고정 |
| 메타 | 대상 · 수집 시각 · 출처. 두 열(라벨 muted 13px 80px 폭 / 값 고정폭 13.5px) | 출처가 길면 줄바꿈 |
| 원문 | 마스킹된 원문. `--surface-2` 블록, 고정폭 13.5px, 가로 스크롤 없이 줄바꿈, 세로는 서랍 높이 안에서 스크롤 | 마스킹은 §5.14. JSON은 들여쓰기 유지 |
| 하단 | `단독 페이지 링크 복사` 버튼 (보조 버튼, §5.8: accent 테두리 + 아이콘) | 주소는 `?ev=N`이 붙은 현재 화면 주소 |

**그려야 할 상태**

| 상태 | 내용 |
|---|---|
| 로그 발췌 | 위 와이어프레임 (근거 14) |
| 규칙 판정 값 | 종류 `detector`, 대상 `dev/Deployment/agent`, 원문은 `Progressing=False`·`progressDeadlineSeconds: 600` 같은 판정에 쓴 값 (근거 7) |
| 긴 원문 | 서랍 안 세로 스크롤, 헤더·하단 고정 |
| 복수·범위 칩에서 열림 | 헤더 아래 번호 알약 `22 · 23 · 24 · 25`, 현재 번호 accent 강조 |
| 근거를 찾을 수 없음 | 빈 상태 (§5.13) |
| `?ev=N` 주소로 직접 진입 | 아래 화면이 그대로 로드되고 서랍이 열린 채로 시작. 닫으면 `?ev`가 지워진 같은 화면 |

### 6.8 이력 질의 채팅 패널

**목적**: 누적된 점검·이슈·보고서를 질문으로 찾고 비교한다. 저장된 이력만 읽고, 새 조사는 `/kg investigate`로 안내한다.

```text

├──────────────────────────────────────────────┤
```

## 9. 하지 않는 것

| 항목 | 이유 |
|---|---|
| 차트·그래프·추세선·실시간 상태 | 상태 대시보드가 아니다 ([기획서 §4.2](01-project-proposal.md)) |
| 리소스 탐색·리소스 필터, 서비스 관계도 | 화면은 점검 시점의 판정 근거만 보인다. 점검 이력의 필터는 점검 행을 거르는 것이지 리소스 필터가 아니다 |
| 로그 검색, 전체 로그 조회 | 근거에는 발췌만 있다 |
| 클러스터 조작 (배포·재시작 버튼) | 모든 도구가 조회 전용이다. 권장 조치는 텍스트와 복사 버튼뿐이다 |
| 증상 입력 폼 | `/kg investigate`는 Slack 명령으로만 ([정의서 §6.5](04-ui-spec.md#65-점검-실행)) |
| GNB의 이동 탭, 레일 옆의 두 번째 사이드바, 상세 페이지 안의 탭 | 이동은 레일(LNB) 하나, 상세는 탭 없는 한 페이지다 ([정의서 §6.2](04-ui-spec.md#62-전체-레이아웃)). 절 바로가기는 탭 모양으로 그리지 않는다 |
| 보고서 목록 페이지, 알림 전용 페이지 | 이슈 목록과 이슈 상세의 타임라인이 대신한다 |
| 프로젝트 선택·로그인 화면, 프로젝트 전환 | 주소(`/p/{p}/…`)와 GNB 자리만 비워 둔다. 프로젝트 표시는 누를 수 없다 ([정의서 §6.2](04-ui-spec.md#62-전체-레이아웃)) |
| 설정 편집 화면 | 점검 구성은 읽기 전용이다. 수정 제안은 사람이 설정 파일에 반영한다 |
| 클러스터를 조회하는 채팅, 새 조사를 시작하는 채팅, 답변 스트리밍, 대화 목록·검색 화면 | 질의 채팅은 저장된 이력만 읽고(대화는 저장하지만 목록 화면은 없다), 새 조사는 `/kg investigate`로 안내한다 ([정의서 §6.7](04-ui-spec.md#67-이력-질의-채팅-패널)) |
| 오른쪽 아래 떠 있는 채팅 버튼, 반짝이·그라데이션 장식 | 질문 버튼은 GNB에만 둔다 |
| 로그인·사용자 메뉴(인증) | PoC는 인증이 없다 ([정의서 §6.8](04-ui-spec.md#68-접근)). 사용자 자리는 비워 둔다 |
| 프롬프트·LLM 응답 원문 | Phoenix에서 본다. 조사 과정에서 링크만 둔다 |
| 테마 토글, 장식 일러스트, 애니메이션 | 서랍·채팅 패널 슬라이드와 조사 과정 단계 갱신 외에는 움직임이 없다 |
