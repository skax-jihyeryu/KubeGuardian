# KubeGuardian AI — UI 디자인 (보고서 화면)

> [UI 정의서](04-ui-spec.md)의 보고서 화면(P1~P5, P3 서랍)을 **그리기 위한** 디자인 문서다. 기능·데이터·라우트는 정의서가 정본이고, 이 문서는 "무엇이 어디에 어떻게 보이는가"를 정한다.
> 기준: 기획서 v3.2 + 결정 이력 10-14까지, [규칙 명세 05-rules.md](05-rules.md). Claude Design으로 목업을 그릴 때 이 문서를 입력으로 쓴다 (§8).
> Slack 메시지 목업은 범위 밖이다. 메시지 형식은 [UI 정의서 §2](04-ui-spec.md#2-메시지-정의)를 본다.

## 0. 목적과 범위

| 항목 | 내용 |
|---|---|
| 목적 | 운영자가 Slack 알림의 링크로 들어와 **원인·근거·조치를 한 화면에서 읽고**, 점검 이력과 조사 과정으로 결론을 믿어도 되는지 확인한다 |
| 그리는 화면 | P1 보고서 목록, P2 보고서 상세, P3 근거 원문(오른쪽 서랍 + 단독 페이지), P4 점검 이력, P5 조사 과정 ([정의서 §6.1](04-ui-spec.md#61-페이지)) |
| 범위 밖 | Slack 메시지 목업, 로그인 화면, 모바일 전용 화면 |
| 화면 성격 | **점검 시점에 고정된 판정 근거를 읽는 문서형 화면.** 상태 대시보드가 아니다. 차트·실시간 그래프·리소스 탐색이 없다 ([정의서 §6.8](04-ui-spec.md#68-경계)) |
| 사용 환경 | 업무 노트북 브라우저 1280~1440px 기준. 960px 이하에서도 깨지지 않아야 한다 (모바일 최적화는 아님). 발표 때 화면을 투사하므로 글자가 작아 보이지 않아야 한다 |
| 구현 | 서버 렌더링 HTML(Jinja2 + HTMX). 디자인은 CSS 변수와 표준 HTML 요소로 구현할 수 있는 범위로 그린다 (프론트 프레임워크·아이콘 라이브러리 없음) |

## 1. 디자인 원칙

| # | 원칙 | 그림에서 지키는 법 |
|---|---|---|
| 1 | **문서처럼 읽힌다** | 위에서 아래로 한 열로 읽는다. 카드를 겹겹이 쌓지 않고, 제목·본문·표로 구성한다. 한 줄 길이는 본문 기준 약 70자를 넘기지 않는다 |
| 2 | **색은 의미에만 쓴다** | 파랑 = 클릭할 수 있는 것(링크·버튼·근거 칩). 상태색 = 심각도·상태만. 장식용 그라데이션·색 배경 영역을 만들지 않는다 |
| 3 | **정상은 조용하다** | 통과·정상·해결은 회색 글자와 작은 표시로 줄인다. 눈에 띄는 색은 적발·긴급·주의·확인 못함에만 쓴다 |
| 4 | **근거 번호가 항상 눈에 띈다** | `[근거 N]` 칩은 본문 글자보다 한 단계 진한 파랑 배경으로, 문장 끝에서 바로 찾을 수 있다. 근거가 없는 문장은 _(추정)_ 이 붙어 다르게 보인다 |
| 5 | **심각도는 색만으로 구분하지 않는다** | 심각도·상태는 항상 이모지와 라벨을 함께 쓴다 (색각 이상, 흑백 인쇄, 투사 화면 대비) |
| 6 | **밀도는 높게, 위계는 분명하게** | 한 화면에 많은 정보를 담되, 제목 → 결론 → 근거 순으로 크기·굵기 차이로 위계를 만든다. 간격은 4px 배수만 쓴다 |

## 2. 색 테마

**라이트가 기본이고, OS가 다크 설정이면 다크로 자동 전환한다** (`prefers-color-scheme: dark`). 사용자가 고르는 토글은 두지 않는다. 토큰은 [진행 보고 HTML](presentation/2026-10-20-progress.html)의 값을 이어받아 상태색을 6종으로 늘렸다.

### 2.1 바탕·글자·강조

대비는 WCAG 상대 휘도 기준 비율이다 (계산 방법은 §2.4). 기준: 본문·작은 글자 4.5:1 이상.

| 토큰 | 라이트 | 다크 | 용도 | 대비(라이트 / 다크) |
|---|---|---|---|---|
| `--bg` | `#f7f7f5` | `#141416` | 페이지 바탕 | — |
| `--surface` | `#ffffff` | `#1d1d20` | 본문 면, 표, 서랍 | — |
| `--surface-2` | `#f0f0ec` | `#26262b` | 코드·근거 원문 블록, 호버 | — |
| `--line` | `#e3e3e0` | `#2e2e33` | 구분선, 테두리 | — |
| `--ink` | `#1d1d1f` | `#ececee` | 본문 글자 | surface 위 16.83 / 14.25 |
| `--muted` | `#6b6b70` | `#9a9aa2` | 보조 글자, 메타, 통과 항목 | surface 위 **5.30 / 6.02**, surface-2 위 4.64 / 5.39 |
| `--accent` | `#2f5bea` | `#7b9bff` | 링크·버튼·근거 칩 글자·진행 중 | surface 위 5.52 / 6.39, accent-soft 위 4.75 / 5.23 |
| `--accent-soft` | `#e8eefe` | `#232c48` | 근거 칩·선택·진행 중 배경 | — |

### 2.2 상태색

상태마다 세 값을 둔다. **text**는 글자·아이콘 선(작은 글자 가능), **dot**은 점·왼쪽 막대·진행도 막대(글자에 쓰지 않음), **soft**는 배지·배너 배경이다.

**라이트**

| 상태 | 이모지·라벨 | text | dot | soft | text/surface | text/soft | dot/surface |
|---|---|---|---|---|---|---|---|
| 긴급 (빨강) | 🔴 긴급 | `#b42318` | `#d92d20` | `#fdeceb` | 6.57 | 5.75 | 4.83 |
| 주의 (주황) | 🟠 주의 | `#9a4a00` | `#e8710a` | `#ffeedd` | 6.26 | 5.52 | 3.09 |
| 잠재 위험 (노랑) | 🟡 잠재 위험 | `#6b5900` | `#b38600` | `#fbf3cc` | 6.88 | 6.15 | 3.32 |
| 개선 권고 (회색) | ⚪ 개선 권고 | `#55555b` | `#85858c` | `#ececea` | 7.40 | 6.26 | 3.66 |
| 진행 중 (=accent 파랑) | 🔍 진행 중 | `#2f5bea` | `#2f5bea` | `#e8eefe` | 5.52 | 4.75 | 5.52 |
| 정상·복구 (초록) | ✅ 정상·복구 | `#13693a` | `#2e9e5b` | `#e2f4e9` | 6.75 | 5.90 | 3.41 |

**다크**

| 상태 | text | dot | soft | text/surface | text/soft | dot/surface |
|---|---|---|---|---|---|---|
| 긴급 | `#ff8a7d` | `#f0584a` | `#3b1f1c` | 7.35 | 6.57 | 4.96 |
| 주의 | `#ffa24d` | `#f58a2a` | `#3a2512` | 8.43 | 7.24 | 6.85 |
| 잠재 위험 | `#e8c95a` | `#d9b72c` | `#342d12` | 10.36 | 8.45 | 8.62 |
| 개선 권고 | `#b4b4bb` | `#7c7c85` | `#2b2b30` | 8.16 | 6.83 | 4.07 |
| 진행 중 | `#7b9bff` | `#7b9bff` | `#232c48` | 6.39 | 5.23 | 6.39 |
| 정상·복구 | `#5cc98a` | `#3fb26f` | `#1b3326` | 8.15 | 6.57 | 6.25 |

- 모든 text 값이 surface와 자기 soft 위에서 4.5:1 이상이다. `--muted`는 surface 위에서 라이트 5.30, 다크 6.02다.
- dot은 글자가 아니라 도형이므로 비텍스트 대비 기준(3:1)을 목표로 했다. 라이트의 주황 3.09가 가장 낮다.
- **색상(hue) 구분**: 라이트 text 기준 빨강 4° · 주황 29° · 노랑 50°, 다크는 6° · 29° · 47°다. 빨강과 주황 25° 이상, 주황과 노랑 21° 이상 떨어져 있다. 그래도 나란히 놓으면 구분이 약할 수 있으므로 **이모지와 라벨을 항상 함께 쓴다.**
- 진행 중은 별도 파랑을 만들지 않고 `--accent`를 쓴다. "클릭할 수 있음"과 "진행 중"이 같은 파랑이므로, 진행 중은 항상 🔍와 라벨을 붙이고 클릭 대상에는 밑줄·테두리를 둔다.

### 2.3 특수 상태의 표시

색 하나로 만들지 않고 테두리·아이콘·배경 조합으로 구분한다.

| 상태 | 표시 | 이유 |
|---|---|---|
| ⚠️ 미완·중단 (조사 미완, 조사 실패, 점검 중단) | 주의 주황 **테두리**(1px, dot 색) + ⚠️ 아이콘 + 라벨. 배경은 surface | 심각도 주의(🟠)와 같은 계열이지만, 채움 배경이 없고 ⚠️가 붙어 구분된다 |
| 관찰 중 | 회색 **점선** 테두리 + 지속 시간 진행도(예: `15분 중 10분째`와 가는 막대) | 아직 적발이 아니므로 상태색을 쓰지 않는다 |
| 확인하지 못함 | 회색 soft 배경 + ⊘ 아이콘 + 못 읽은 kind·사유 | 통과도 적발도 아님. 읽지 못했다는 사실이 보여야 한다 |

### 2.5 대비 검증

임시 Python 스크립트로 WCAG 2.x 상대 휘도 공식에 따라 위 표의 모든 쌍을 계산했다 (스크립트는 레포 밖에 있고 커밋하지 않았다). 값을 바꾸면 같은 계산으로 다시 확인한다. 기준은 text 쌍 4.5:1 이상, `--muted` on `--surface` 4.5:1 이상이다.

## 4. 기본 레이아웃

### 4.1 상단 바와 본문

```text
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ KubeGuardian   [dev]   보고서   점검 이력                       마지막 점검 14:15 ✅   │ 56px
├────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                        │
│            ┌──────────────────────── 본문 (최대 폭 1200px, 가운데) ───────────────┐   │
│            │                                                                      │   │
│            │   페이지 제목                                                        │   │
│            │   본문 …                                                             │   │
│            └──────────────────────────────────────────────────────────────────────┘   │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

| 영역 | 내용 |
|---|---|
| 상단 바 | 높이 56px, `--surface` 배경, 아래 1px `--line`. 화면 폭 전체에 고정(스크롤해도 보임) |
| 왼쪽 | 로고 텍스트 **KubeGuardian**(600, 16px) · 네임스페이스 배지 `dev`(고정폭, 알약, `--surface-2`) · 탭 **보고서** / **점검 이력** (현재 탭은 아래 2px accent 밑줄 + ink 글자) |
| 오른쪽 | 마지막 점검 상태 한 줄: `마지막 점검 14:15 ✅`. 마지막 점검이 이상이면 가장 높은 심각도 이모지(`14:40 🔴`), 점검 중이면 `🔍`, **점검이 멈췄으면 ⚠️** `점검 15분째 안 됨 · 마지막 정상 14:05`(주황 text, 클릭하면 점검 이력). 클릭하면 점검 이력으로 이동 |
| 본문 | 최대 폭 1200px, 가운데 정렬, 좌우 24px, 위 32px |
| P5 조사 과정 | 탭에 두지 않는다 (점검 이력·보고서에서만 들어간다). 상단 바에서는 `점검 이력` 탭이 현재 탭으로 표시된다 |

### 4.2 P2 — 본문 + 오른쪽 메타 열

```text
┌───────────────────────────── 본문 1200px ─────────────────────────────────┐
│ ┌──────────────── 보고서 (약 880px) ──────────────┐ ┌── 메타 열 300px ──┐ │
│ │ [조사 보고서] 제목                    🔴 긴급    │ │ 보고서 R-0412     │ │
│ │ ■ 중요 문제                                      │ │ 상태 ● 열림       │ │
│ │ ■ 결론                                           │ │ 심각도 / 확신도   │ │
│ │ ■ 근거                                           │ │ 감지 14:05 (주기) │ │
│ │ ■ 가설 판정                                      │ │ 에이전트 …        │ │
│ │ ■ 확인한 범위                                    │ │ 조사 48s·도구 9회 │ │
│ │ ■ 권장 조치                                      │ │ 조사 과정 보기 ▸  │ │
│ │ ■ 재검증 방법                                    │ │  (sticky, 위 72px)│ │
│ │ ■ 참고 — 개선 권고                               │ └───────────────────┘ │
│ │ ■ 알림 이력                                      │                       │
│ └──────────────────────────────────────────────────┘                       │
└────────────────────────────────────────────────────────────────────────────┘
```

- 메타 열은 스크롤해도 상단 바 아래 16px에 붙는다 (`position: sticky`). 보고서 본문과 `24px` 간격이다.
- 메타 열 내용은 [정의서 §6.2](04-ui-spec.md#62-p2-보고서-상세-구성)의 하단 요약 줄(조사 48초 · 도구 호출 9회 · 2.1만 토큰 · 참고한 지침)을 여기로 옮긴 것이다. 내용은 같고 위치만 다르다.

### 4.3 P3 — 오른쪽 서랍

```text
┌───────────────────────────────── 보고서 (스크롤 위치 유지) ──┬──── 서랍 520px ────┐
│ (배경이 어두워진다: 검정 40% 투명)                         │ [근거 14]       ✕  │
│                                                            │ log_excerpt        │
│                                                            │ 대상 / 수집 / 출처 │
│                                                            │ ┌────────────────┐ │
│                                                            │ │ 마스킹된 원문  │ │
│                                                            │ └────────────────┘ │
│                                                            │ 단독 페이지 링크 ⧉ │
└────────────────────────────────────────────────────────────┴────────────────────┘
```

| 항목 | 규칙 |
|---|---|
| 폭·위치 | 오른쪽에서 밀려 들어오는 520px 서랍, 높이는 화면 전체. 모서리 반경은 왼쪽 위·아래 12px |
| 배경 | 서랍 밖 영역을 검정 40% 투명으로 어둡게 한다. 보고서 스크롤 위치는 그대로다 |
| 닫기 | **Esc**, 서랍 밖(어두운 영역) 클릭, 오른쪽 위 ✕ 버튼 |
| 단독 URL | 서랍 아래(또는 헤더)에 `단독 페이지 링크 복사` 버튼. 눌러 `/evidence/{id}` 주소를 복사하고 "복사했습니다"를 2초 보인다. 같은 링크를 새 탭에서 열면 서랍 없이 P3 단독 페이지로 보인다 |
| 960px 이하 | 서랍이 전체 폭을 차지한다 |

### 4.4 960px 이하

| 영역 | 변화 |
|---|---|
| 본문 | 좌우 16px. 표는 가로 스크롤 없이 줄바꿈하고, 열이 많은 P4 행은 두 줄(시각·심각도 / 요약)로 접힌다 |
| P2 메타 열 | 본문 **위**로 올라가 한 덩어리(접힘 없음)로 보이고 sticky를 푼다 |
| 서랍 | 전체 폭 |
| 상단 바 | 탭은 유지하고 오른쪽 점검 상태는 이모지 + 시각만 남긴다 |

### 4.5 페이지 이동 관계

```text
Slack M1·M2·M3·M6 링크 ───────────────▶ P2 보고서 상세
Slack M7 점검 중단 링크 ──────────────▶ P4 점검 이력
상단 바 오른쪽 "마지막 점검" ─────────▶ P4
P1 보고서 목록 ── 행 클릭 ────────────▶ P2
P2 ── [근거 N] ───────────────────────▶ P3 서랍 (같은 화면 위, 단독 URL로도 열림)
P2 ── 조사 과정 보기 ─────────────────▶ P5 (해당 점검)
P2 ── 알림 이력 항목 ─────────────────▶ (같은 화면에서 메시지 본문 펼침)
P4 점검 이력 ── 보고서 R-0412 ────────▶ P2
P4 ── 행의 "조사 과정 보기" ──────────▶ P5
P4 ── 지금 점검 실행 ─────────────────▶ P5 (진행 중 화면으로 이동)
P5 ── 도구 호출의 [근거 N] ───────────▶ P3 서랍
P5 ── 보고서 R-0412 ──────────────────▶ P2
P5 ── Phoenix 추적 열기 ↗ ────────────▶ 외부 (Phoenix)
```

## 5. 공통 컴포넌트

공통 모양: 높이는 크기별(sm 20px · md 24px · lg 32px), 글자는 text 값, 배경은 soft 값, 반경 999px, 가로 패딩 8px, 이모지와 라벨 사이 4px.

### 5.1 심각도 배지 (7종)

| 배지 | 라벨 | 색 | 쓰는 곳 |
|---|---|---|---|
| 🔴 | 긴급 | 긴급 text/soft | P1 행, P2 제목, P4 행, 중요 문제 목록 |
| 🟠 | 주의 | 주의 text/soft | 위와 같음 |
| 🟡 | 잠재 위험 | 잠재 위험 text/soft | P1·P2 (알림 없는 참고 문제) |
| ⚪ | 개선 권고 | 개선 권고 text/soft | P2 "참고 — 개선 권고", H01·H02 |
| 🔍 | 진행 중 | accent text / accent-soft | P4 점검 중, P5 진행 중, 상단 바 |
| ⚠️ | 미완·중단 (라벨은 "조사 미완" · "조사 실패" · "점검 중단") | 주황 **테두리** + 아이콘, 배경 surface | P2 제목 앞, P4 중단 구간, 상단 바 |
| ✅ | 정상·복구 | 정상 text/soft | P4 행, P2 복구 이력, 상단 바 |

- 목록 행의 왼쪽에는 4px 세로 막대를 dot 색으로 둔다. 막대는 장식이 아니라 심각도의 보조 표시이며, 배지가 항상 같이 있다.
- 정상 행은 막대와 배경 없이 `✅ 이상 없음`을 muted 글자로 보인다.

### 5.2 1차 → 최종 심각도

| 상황 | 표시 |
|---|---|
| 같음 | 최종 배지만 보인다 |
| 바뀜 | 최종 배지 오른쪽에 muted 13px로 `1차 🟠 주의 → 🔴 긴급`. 1차 이모지는 회색 글자와 함께 보이고 화살표 오른쪽이 현재 값이다 |
| Service 수집 실패로 낮아짐 | `1차 🟠 주의 (Service 수집 실패로 낮춤)`. 낮춘 사유가 같은 줄에 붙는다 ([05-rules §0.3](05-rules.md#03-묶음용-데이터를-수집하지-못했을-때)) |
| 조사 전 | 1차 심각도만 보이고 `조사 중` 배지가 옆에 붙는다 |

P1 행에서는 배지 아래 줄에, P2에서는 제목 오른쪽 배지 아래 줄에 쓴다.

### 5.3 문제 상태

| 상태 | 모양 |
|---|---|
| 열림 | 1px `--line` 테두리 알약, ink 글자 `열림`, 앞에 심각도 dot 색 ● |
| 해결 | 테두리 없음, muted 글자 `✓ 해결 14:45` (해결 시각) |

### 5.4 확신도

`높음` `중간` `낮음` 글자와 3칸 점으로 보인다: `●●● 높음` / `●●○ 중간` / `●○○ 낮음`. 점 색은 ink(채움)·line(빈칸)이고 **상태색을 쓰지 않는다** (심각도와 헷갈리지 않게). 크기 13px, 점 지름 6px.

### 5.5 근거 칩

| 형태 | 모양 |
|---|---|
| `[근거 14]` | 고정폭 13px, `--accent` 글자, `--accent-soft` 배경, 반경 6px, 높이 22px, 가로 패딩 6px. 호버에 밑줄, 포커스에 윤곽 |
| `[근거 14, 15]` | 칩 하나 안에 번호 두 개. 번호마다 클릭 대상이 따로 있다 |
| `[근거 22~25]` | 칩 하나. 누르면 22번을 서랍에 열고, 서랍 헤더에 `22 · 23 · 24 · 25` 번호 알약이 나타나 서로 오갈 수 있다 |
| 문장 안 위치 | 문장 끝 마침표 앞, 앞 글자와 4px 띄운다 |
| 서랍이 열린 동안 | 열려 있는 칩은 accent 배경을 진하게 한다 (accent 글자를 배경으로, 글자는 surface) |
| 존재하지 않는 번호 | 칩이 회색 점선 테두리로 보이고 누르면 서랍에 "근거를 찾을 수 없습니다" 빈 상태 |

### 5.6 추정 표기

문장 끝에 _(추정)_을 붙인다 (기울임, muted, 14px). 근거 칩이 있어야 할 자리에 칩이 없고 _(추정)_만 있다는 점이 눈에 띄어야 한다. 배경색은 두지 않는다.

### 5.7 규칙 판정 칩 (4종)

[05-rules §0.1](05-rules.md#01-판정-결과)의 판정 4가지다. 칩은 P4의 규칙 행과 P5 게이트 단계에서 쓴다.

| 판정 | 모양 | 함께 보이는 값 |
|---|---|---|
| **적발** | 1차 심각도의 배지(🔴·🟠·⚪)에 `적발` 글자. 행 왼쪽에 심각도 막대 | 규칙 ID(고정폭), 대상, 판정에 쓴 값 |
| **관찰 중** | 회색 **점선** 테두리 알약 `관찰 중`. 옆에 `15분 중 10분째`와 가는 진행 막대(전체 폭 80px, 높이 4px, `--line` 바탕 위에 `--tip-dot` 채움) | 최초 관측 시각 |
| **통과** | 칩 없이 muted 글자 `✓ 통과` | 판정에 쓴 값 (예: `Endpoint Ready 3/3`) |
| **확인하지 못함** | `--tip-soft` 배경 알약 `⊘ 확인하지 못함` | 못 읽은 kind와 사유 (예: `EndpointSlice — Kubernetes API 응답 없음`) |

### 5.8 점검 실행 버튼 (3상태)

| 상태 | 모양 | 동작 |
|---|---|---|
| 가능 | accent 배경 버튼, surface 글자 `지금 점검 실행`, 높이 36px, 반경 8px | 누르면 P5로 이동 |
| 진행 중 | 비활성(회색 `--tip-soft` 배경, muted 글자) `점검이 진행 중입니다`, 아래에 accent 링크 `진행 중인 점검 보기 ▸` (P5) | 누를 수 없다 |
| 쿨다운 | 비활성 `1분 뒤에 다시 실행할 수 있습니다 · 남은 시간 0:42`, 숫자는 tabular-nums로 1초마다 줄어든다 | 0:00이 되면 가능 상태로 돌아간다 |

### 5.9 접이식 단계 (타임라인)

P5의 단계 목록이다. 세로선(1px `--line`)에 단계 점을 두고, 단계 제목 줄을 눌러 접고 편다.

| 상태 | 모양 |
|---|---|
| 접힘 | `▸ 단계 이름   요약 한 줄   시작 14:10:03 · 2s` |
| 펼침 | `▾` + 아래 들여쓴 본문 (도구 호출 행, 신호판 표 등) |
| 완료 | 점은 속이 찬 muted 색, 소요 시간 표시 |
| 현재 단계 (진행 중) | 점이 accent로 채워지고 점 주위에 2px accent 링, 행 배경 `--accent-soft`, 제목 굵게 + `🔍 진행 중` |
| 아직 안 한 단계 | 빈 점(테두리만), 글자 muted |
| 상한 도달·실패한 단계 | 주황 테두리 점 + ⚠️ |

### 5.10 도구 호출 행

한 줄 구조: `도구이름(인자)  →  결과 요약   [근거 N]   (원문 ▸)`.

| 요소 | 모양 |
|---|---|
| 도구 이름·인자 | 고정폭 13.5px, ink. 인자는 muted |
| 결과 요약 | 본문 14px |
| 근거 | 근거 칩 (누르면 P3 서랍) |
| 원문 ▸ | accent 링크. 눌러 인자 전체와 요약 결과를 아래로 펼친다 (프롬프트·LLM 응답은 없다) |
| 상한에 걸려 못 한 호출 | 행은 없고 단계 아래에 `⚠️ 상한 도달로 이후 호출 생략` 한 줄 |

### 5.11 알림 이력 항목

| 요소 | 모양 |
|---|---|
| 줄 | `14:05  최초 감지   [보냄]   메시지 본문 보기 ▾` 시각은 고정폭, 종류(최초 감지 · 원인 갱신 · 리마인더 · 복구) 굵게 |
| **보냄** 배지 | 정상 text/soft, `보냄` |
| **dry-run 기록** 배지 | 개선 권고 회색 text/soft, `dry-run 기록` (평가 중·Slack 승인 전에 기록만 한 메시지). 줄 전체를 muted로 둔다 |
| 본문 펼치기 | 펼치면 보낸 메시지 본문을 `--surface-2` 블록(고정폭 13.5px)으로 보인다. Slack 링크 자리는 `<보고서 화면 링크>` 그대로 둔다 |
| 시간 순서 | 위가 오래된 것 (최초 감지부터) |

### 5.12 경고 배너

본문 맨 위(제목 바로 아래)에 한 줄 또는 두 줄로 붙는다. 폭 전체, 반경 8px, 패딩 12px 16px, 왼쪽 4px 막대.

| 배너 | 내용 | 색 |
|---|---|---|
| ⚠️ 조사 미완 | `상한에 도달해 조사를 마치지 못했습니다 (도구 20/20). 확인하지 못한 가설은 "확인하지 못함"에 있습니다.` | 주황 테두리(1px) + 주황 막대, 배경 surface |
| ⚠️ 조사 실패 | `조사 중 오류가 발생했습니다: Azure OpenAI 응답 없음. 규칙·증상 결과만 표시합니다.` | 위와 같음 |
| 일부 수집 실패 | `일부 항목을 확인하지 못했습니다 (Kubernetes API 응답 없음). 확인한 결과만 표시합니다.` + 못 읽은 kind 목록 | ⊘ 아이콘, `--tip-soft` 배경 |
| 결론 근거 없음 | 결론 바로 위: `결론이 인용한 근거 없음` | 주의 text/soft, 🟠 아이콘 |
| 점검 중단 | P4 맨 위: `⚠️ 점검이 15분째 실행되지 않았습니다 (마지막 정상 점검 14:05)` | 주황 테두리 + ⚠️ |

### 5.13 빈 상태

| 위치 | 문구 | 이어지는 동작 |
|---|---|---|
| P1 기록 없음 | `아직 점검 기록이 없습니다.` 보조: `점검 이력에서 점검을 실행할 수 있습니다.` | `점검 이력으로 ▸` 링크 |
| P1 열린 문제 없음 (필터 열림) | `열린 문제가 없습니다.` | — |
| P4 기록 없음 | `점검 기록이 없습니다. 주기 점검은 5분마다 실행됩니다.` | 점검 실행 버튼 |
| P3 근거 없음 | `근거를 찾을 수 없습니다.` | 서랍 닫기 |
| P2 알림 이력 없음 | `보낸 알림이 없습니다 (참고 문제는 알림 없이 화면에만 표시됩니다).` | — |

빈 상태는 중앙 정렬 아이콘 없이 muted 글자 두 줄과 링크 하나로만 보인다 (그림·일러스트 없음).

### 5.14 마스킹 표시

마스킹된 값은 `****`로 보이고 고정폭이다. 키 이름(`password`, `Authorization` 등)은 보이고 값만 가려진다. 배경 강조나 자물쇠 아이콘은 쓰지 않는다. 근거 원문과 알림 본문 모두 같다.

```text
LLM_API_KEY=****
Authorization: Bearer ****
postgres://app:****@postgres:5432/app
```

## 6. 페이지별 화면

### 6.1 P1 — 보고서 목록

**목적**: 최근 보고서를 시각순으로 훑고 열린 문제부터 찾는다.

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 보고서                                    [ 전체 3 ] [ 열림 1 ] [ 해결 2 ]    │
├────┬─────────┬───────────────────────────────────────────────┬──────┬────────┤
│시각│ 심각도  │ 제목                                          │확신도│ 상태   │
├────┼─────────┼───────────────────────────────────────────────┼──────┼────────┤
│▌14:05│🔴 긴급  │ R-0412  채팅 실패 — llm-gateway 할당량 소진    │●●● 높음│● 열림 │
│▌11:25│🟠 주의  │ R-0411  신규 배포가 뜨지 않음 — 없는 이미지 tag │●●● 높음│✓ 해결 │
│▌09:05│🔴 긴급  │ R-0410  agent 기능 전부 실패 — Service 대상 …   │●●● 높음│✓ 해결 │
└────┴─────────┴───────────────────────────────────────────────┴──────┴────────┘
```

| 영역 | 표시 항목 |
|---|---|
| 제목 줄 | 페이지 제목 `보고서`, 오른쪽에 상태 필터 알약 3개(전체 · 열림 · 해결, 건수 포함). `?status=open\|resolved`와 같다. 현재 필터는 accent 윤곽 |
| 목록 | 열: 시각(`HH:MM`, 날짜가 다르면 `MM-DD HH:MM`) · 심각도 배지(1차와 다르면 아래 줄에 `1차 🟠 주의 → 🔴 긴급`) · 보고서 ID와 제목 · 확신도 · 상태. 행 전체가 링크(→ P2), 호버에 `--surface-2` |
| 행 | 높이 44px 이상. 열린 문제는 왼쪽 막대를 심각도 dot 색으로, 해결된 문제는 막대 없이 행 전체를 muted로 줄인다 |
| 정렬 | 최신이 위. 열린 문제가 해결된 문제보다 항상 위는 아니다 (시각순만) |

## 9. 하지 않는 것

| 항목 | 이유 |
|---|---|
| 차트·그래프·추세선·실시간 상태 | 상태 대시보드가 아니다 ([기획서 §4.2](01-project-proposal.md)) |
| 리소스 탐색·필터, 서비스 관계도 | 화면은 점검 시점의 판정 근거만 보인다. 상태 필터(열림/해결)만 P1에 있다 |
| 로그 검색, 전체 로그 조회 | 근거에는 발췌만 있다 |
| 클러스터 조작 (배포·재시작 버튼) | 모든 도구가 조회 전용이다. 권장 조치는 텍스트와 복사 버튼뿐이다 |
| 증상 입력 폼 | `/kg investigate`는 Slack 명령으로만 ([정의서 §6.5](04-ui-spec.md#65-점검-실행)) |
| 로그인·사용자 메뉴 | PoC는 인증이 없다 ([정의서 §6.7](04-ui-spec.md#67-접근)) |
| 프롬프트·LLM 응답 원문 | Phoenix에서 본다. P5에서 링크만 둔다 |
| 테마 토글, 장식 일러스트, 애니메이션 | 서랍 슬라이드와 P5 단계 갱신 외에는 움직임이 없다 |
