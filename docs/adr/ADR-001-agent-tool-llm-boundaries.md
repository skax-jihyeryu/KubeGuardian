# ADR-001: 도구 계층·에이전트 base·LLM 생성의 경계

- 상태: 채택
- 날짜: 2026-10-15
- 관련: W1, #10 기반 계약, #14 에이전트·도구 기반, 실행 계획서 §1.3, 기획서 §6.1·§10

## 배경

- 조사 에이전트는 기본 구현(LangGraph)과 비교 실험 1(직접 구현한 도구 호출 루프)을 **같은 도구·같은 시나리오**로 비교해야 한다 (기획서 §10).
- 이후 다른 에이전트(예: 조치 에이전트)와 새 버전이 붙고, 모델도 바뀔 수 있다.
- 도구 결과에는 비밀값이 섞일 수 있고, 진단 대상 네임스페이스 밖을 조회하면 안 된다 (기획서 §6.5·§13).
- 이 규칙을 에이전트 구현마다 따로 지키면 비교 실험의 조건이 달라지고, 한 곳만 빠뜨려도 비밀값이 LLM·Slack으로 나간다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 도구를 LangChain `@tool` 함수로 바로 만들고 에이전트가 직접 LLM 클라이언트를 만든다 | 코드가 가장 적다 | 직접 구현 루프·MCP 서버가 같은 도구를 쓰려면 LangChain에 묶인다. 마스킹·범위 검사가 도구마다 흩어진다. 모델·제공사 변경이 에이전트 코드에 퍼진다 |
| B. 도구·에이전트·LLM 생성을 세 계층으로 나누고, 공통 규칙은 각 계층의 base에서 강제한다 | 구현 방식을 바꿔도 도구·평가가 그대로다. 규칙을 한 곳에서 테스트한다 | 얇은 인터페이스·어댑터 코드가 생긴다 |

## 결정

**B**를 택한다.

| 계층 | 위치 | 책임 | 모르는 것 |
|---|---|---|---|
| 도구 | `service/tools/` — `Tool`, `ToolContext`, `ToolResult` | `Tool.run`이 입력 검증 → 대상 네임스페이스 고정 → 수집 → **마스킹** → 근거 저장 → 요약 반환을 강제한다. 구현은 `collect()`만 쓴다 | LangGraph, LLM |
| 에이전트 | `service/agent/` — `BaseAgent`, `AgentSpec`, `registry`, `_common/` | `run(InvestigationRequest) -> AgentResult`. `<이름>/v<N>/` 폴더로 구현을 나누고 `"이름:버전"` 키로 고른다. 도구는 `_common/tool_adapter.py`가 LangChain 도구로 바꾸고 결과를 `<tool_output>`으로 감싼다 | 제공사, 엔드포인트, 키 |
| LLM 생성 | `core/llm.py` — `build_chat_model(model)` | 제공사 분기와 연결 설정(환경 변수)을 한 곳에 둔다 | 어떤 역할에 어떤 모델을 쓰는지 |

- **어떤 모델을 쓸지는 에이전트 버전의 `AgentSpec.models`(역할 → 모델)**가 정한다. 모델을 바꾸는 것은 새 버전이거나 그 버전 설정의 변경이므로 리뷰·eval 비교 대상이 된다.
- 에이전트는 LLM을 직접 만들지 않고 생성자로 받은 `llm_factory`(운영에서는 `build_chat_model`)를 역할 이름으로 부른다. 그래서 테스트는 가짜 LLM으로 같은 코드를 돌린다.
- 구조화 출력은 `_common/structured.py`가 코드펜스·설명문을 견디고 1회 재시도한다. 형식이 맞아도 근거 번호 검증은 별도 가드레일(`core/guard`)이 한다.
- 근거 저장소는 `EvidenceSink.add(evidence) -> "ev-0001"` 하나로 도구와 연결한다 (구현: `core/db`).

## 결과

- 비교 실험 1(`investigator/v1_loop`)과 비교 실험 3(MCP 서버)은 `Tool`을 그대로 쓰고 어댑터만 새로 만든다.
- 도구 결과의 마스킹·범위 검사는 `tests/service/tools/test_base.py`가 한 번에 검증한다. 새 도구는 `collect()`만 테스트하면 된다.
- 다른 제공사를 붙일 때는 `core/llm.py`에 분기를 더하고, 도구 호출·구조화 출력이 같은지 eval로 확인한다.
- 다시 볼 조건: 도구 결과를 스트리밍해야 하거나, 에이전트가 도구를 동적으로 만들어야 해서 `Tool`의 동기 `run` 형태가 맞지 않을 때.
