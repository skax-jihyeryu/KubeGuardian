# 1. 역량 및 기술 스택 확인

> 프로젝트: KubeGuardian AI — AI 기반 Kubernetes 서비스 환경 진단 Agent (1인 · 8주 · 주 10~15시간)

## 1. 현재 보유 역량

- Python 숙련도: **고급** — FastAPI 계층형 백엔드(routes–service–repository), async SQLAlchemy, Pydantic 검증, 외부 API 연동(재시도·타임아웃)을 실무에서 설계·구현
- AI/ML 경험: 모델 학습보다 **LLM 기반 AI 서비스의 설계·구축·운영** 중심. LLM 결합 데이터 파이프라인(수집 → 정제 → 유사도 중복 제거 → LLM 관련성 판정, Prefect 병렬 실행), 운영 데이터(Databricks·AWS)로 에이전트 응답 이슈 원인 분석
- LLM 활용 경험: Azure OpenAI, AWS Bedrock, LangGraph, LangChain, DeepAgents, Structured Output, Arize Phoenix 트레이싱. 룰 기반 선판정으로 LLM 호출을 줄이는 **룰 + LLM 결합 구조** 설계
- RAG/Agent 구현 경험: **유**
  - Agent: LangGraph 기반 PR 보도자료 작성 에이전트(Router 노드 분기, 자료 유형별 검색 Tool Calling, Checkpointer 세션 관리), 운영 에이전트를 DeepAgent 구조(계획·하위 작업 위임)로 전환
  - RAG: 하이브리드 검색(BM25 + KNN을 RRF로 결합, 필드별 가중 KNN), AWS OpenSearch·Upstage 임베딩
  - 부족한 부분: 에이전트 결과의 **정답 기반 정량 평가**, Kubernetes 장애의 **원인 분석**
- 프로젝트 경험:
  1. **SK Inc. AI Agent 구축·'26 안정화** — LangGraph 에이전트와 하이브리드 RAG 구현, FastAPI·PostgreSQL 백엔드 개발. 안정화 과제에서 DeepAgent 전환, AWS EKS 운영 인프라 정리, 장애 대응
  2. **BeingAX AI Agent — PR 뉴스 모니터링** — 룰 + LLM 판정 구조로 비용·일관성 확보, Airflow 구조를 Prefect 워커–FastAPI 분리 아키텍처로 재설계

## 2. 학습 필요 영역

- LangChain/LangGraph 기초: 실무 보유 → 기초 학습 대신 **가설 → 도구 검증 → 판정** 형태의 조사형 에이전트 설계로 심화
- RAG (Retrieval-Augmented Generation) 구현: 실무 보유 → 이번 프로젝트에서는 조사 지침 문서를 필요한 것만 불러오는 수준으로만 사용
- Multi-Agent 시스템 설계: 실무 보유(DeepAgents) → 단일 에이전트로 충분, 필요 시 가설별 하위 조사로 확장
- Vector DB 활용 (FAISS, Chroma 등): 실무 보유(OpenSearch KNN) → 지침 문서 규모가 작아 이번에는 사용하지 않음
- 프롬프트 엔지니어링: 실무 보유 → 사실 문장마다 근거 인용 강제, 장애 유형별 조사 전략으로 심화
- API 개발 (FastAPI): 실무 보유 → 그대로 활용
- UI 개발 (Streamlit): 미보유 → 운영자 화면은 Slack, 개발·디버깅 화면은 같은 Python 계열인 Chainlit으로 대체
- **추가 — Kubernetes 장애 분석 (중점)**: 리소스 모델, Service 라우팅, 설정 참조, RBAC, CronJob을 규칙 점검 코드와 장애 재현으로 학습
- **추가 — 에이전트 정량 평가 (중점)**: 정답 데이터 설계, 지표 정의, 자동 채점 러너, 기준 조건 대비 비교
- 추가 — 장애 주입(Chaos Mesh), Slack 앱 연동(Socket Mode), MCP(비교 실험)

## 4. 프로젝트 관심 도메인

- 1순위 도메인: **미디어/홍보(PR)**
- 2순위 도메인: **제조(반도체)**
- 관심 사유: KubeGuardian 자체는 산업 중립적인 IT 운영 도구라, **진단 대상 서비스의 도메인**으로 연결한다.
  - 미디어/홍보: 진단 대상 템플릿의 대표 서비스가 직접 구축·운영한 SK Inc. PR 보도자료 자동화 서비스다. PR 업무는 보도 시점·위기 대응처럼 시간에 민감해 서비스 중단이 곧 업무 중단이며, 실제 운영 장애가 시나리오의 출처다.
  - 제조: SK하이닉스 보안 환경 재구축처럼 네트워크·설정 값이 달라지는 환경의 배포 장애는 KubeGuardian의 설정 대조 점검이 가장 잘 맞는 영역이다.

## 5. 8주 목표 설정

- 기술 목표: **5분 주기 점검 → AI 조사·검증 → 근거 인용 보고서 → Slack 알림**까지 동작하는 Kubernetes 진단 에이전트를 직접 설계·구현하고, K8s 상태로는 원인이 보이지 않는 장애의 원인을 찾게 만든다
- 비즈니스 목표: 템플릿 기반 AI 서비스 환경에서 동작하는 진단 에이전트 PoC 완성 — 장애 시나리오 8개에서 원인 정확도 70% 이상, 규칙만 쓸 때 대비 효과를 숫자로 제시
- 성장 목표: **정량적으로 설계하고 숫자로 증명하는 Lv.3 Middle AI 개발자** — 정답 파일·지표를 개발 전에 정의하고, 평가 러너로 자동 측정하고, 기준 조건 대비 결과표와 실패 사례 분석으로 보고. 학습 노트 주 1건, ADR 3건 이상
