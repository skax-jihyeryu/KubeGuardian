# 6. 테스트 및 고도화 (상세본)

> 제출본은 [양식/06](양식/06-테스트및고도화.md)이다. 이 문서에는 제출본에 다 담지 못한 평가 배치별 시나리오 결과와 조사 비용을 모았다. 최종 평가 보고서(이슈 #222)는 아직 열려 있어, 아래는 11월 9일 시점의 측정값이다.

## 1. 평가 방식

* 시나리오: A1(Service selector 오타), A3(해석되지 않는 레지스트리의 이미지), A5(gateway의 하위 서비스 주소 환경변수 4개를 localhost로 변경), B1(agent Pod 3개 중 1개만 모든 응답이 500), C1(llm-gateway의 LLM 응답이 429로 거부), C2(admin과 Redis 사이 패킷 차단으로 로그인 504), 정상 기준선 H0(정상)와 H1(설정이 없어도 정상인 서비스). C1과 C2는 Kubernetes 객체에서 원인이 보이지 않는 시나리오다.
* 실행: 장애를 한 번 주입한 상태에서 AI 조사를 3회 연달아 돌린다. 독립된 장애 주입 3회가 아니므로 에이전트의 편차만 잰다.
* 채점 네 층: 결과(보고서 1순위 원인 리소스를 정답과 코드로 대조하고 결론 문장을 조사와 다른 모델 gpt-4.1이 채점, 둘 다 맞아야 통과), 과정(정답 파일의 핵심 근거를 에이전트가 도구로 직접 얻었는지), 근거(인용한 근거가 문장을 뒷받침하는지 gpt-4.1이 주장별로 채점), 금지(원인이 아닌 것을 원인으로 올렸는지).
* 실패 분류: 도구 한계(정답의 핵심 근거를 현재 도구로는 얻을 수 없음), 탐색 실패(얻을 수 있는 핵심 근거를 못 얻음), 추론 실패(근거는 다 얻었는데 원인을 틀림), 보고 실패(원인 리소스는 맞는데 결론 문장이 불일치), 근거 불일치(맞혔지만 결론이 근거로 뒷받침되지 않음).
* 사람이 직접 채점한 라벨로 gpt-4.1 채점을 보정하는 장치는 만들었으나 라벨이 0건이라 보정은 하지 못했다.

* w4-final은 11/02 19:59부터 21:10까지의 기준선이다. w4-hardening-m3는 11/02 23:44부터 11/03 00:17까지, m4는 11/03 00:18부터 01:04까지다. m3는 로그 조회 등 도구 보강과 미해결 가설 재조사를 함께 적용한 상태이고, m4는 여기에 간헐 실패 Pod별 확인을 더했다. 이 둘을 11월 3일 보강 측정이라 부른다.
* w4-cause-chain-146은 11/03 02:14부터 02:40까지다. 남은 시간 때문에 회귀를 B1 3회, A1과 A5 각 1회, H0와 H1로 줄이고 C2와 A3를 생략했으므로 전체 회귀를 확인했다고 말할 수 없다.
* w4-retest는 11/03 04:22부터 05:39까지다. 첫 C2 실행은 증상이 나지 않아 무효로 처리하고 다시 돌렸다. 이 배치는 레포에 별도 해설 문서가 없어 결과 파일과 리포트 도구로만 확인했다.
* w5-c1-recheck는 11/09 14:21부터 14:30까지 C1만 다시 돌린 배치다. 다른 시나리오를 같은 날 같은 코드로 다시 잰 배치는 w4-retest 이후 없다.
* 11/09에는 C7(서비스 주소 끝에 점이 붙은 오타) 1회도 따로 돌렸고 1/1 통과했다. 배치에 속하지 않은 단일 실행이다.
* 배치마다 시나리오 구성이 달라 원인 정확도끼리 직접 비교할 수 없다.

## 4. C1 분리 비교

배치 w4-c1-tools-vs-recheck(11/03 01:50~02:09)는 C1을 한 번 주입하고, 도구 보강만 한 버전과 미해결 가설 재조사까지 포함한 버전을 같은 Pod의 별도 컨테이너에서 3회씩 돌렸다.

| 버전 | 통과 | 지목한 원인 리소스 | 판단 | 시간 중앙값 | 입력 토큰 중앙값 | 도구 호출 중앙값 |
|---|---|---|---|---|---|---|
| 도구 보강만 | 1/3 | llm-gateway 1회, agent 2회 | 후보 3 | 149.5초 | 224,974 | 15 |
| 재조사 포함 | 0/3 | agent 3회 | 후보 3 | 168.6초 | 340,615 | 20 |

* 결론 문장 채점은 6회 중 5회를 일치로 봤지만 원인 위치 일치는 1회뿐이었다. 의미 채점만으로 원인 위치가 좋아졌다고 말할 수 없다.
* 표본이 작아 재조사의 단독 영향은 단정하지 않는다.
* C1은 HTTPChaos가 앱 처리 뒤에 응답을 바꾸므로 llm-gateway 자기 로그에는 429가 남지 않고, 호출한 agent 로그에만 남는다. 그래서 호출자와 호출 대상 중 어디가 원인인지 구분하기 어렵다. 이 한계를 반영해 평가 기준을 다시 정의하는 일이 열린 이슈 #182다.
