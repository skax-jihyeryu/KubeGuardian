# 6. 테스트 및 고도화 (상세본)

> 제출본은 [양식/06](양식/06-테스트및고도화.md)이다. 이 문서에는 제출본에 다 담지 못한 평가 배치별 시나리오 결과와 조사 비용을 모았다. 2~4절에는 11월 9일까지의 측정값을, 5절에는 11월 9~10일 C1·C2 튜닝 비교를 정리했다.

## 1. 평가 방식

* 시나리오: A1(Service selector 오타), A3(해석되지 않는 레지스트리의 이미지), A5(gateway의 하위 서비스 주소 환경변수 4개를 localhost로 변경), B1(agent Pod 3개 중 1개만 모든 응답이 500), C1(llm-gateway의 LLM 응답이 429로 거부), C2(admin과 Redis 사이 패킷 차단으로 로그인 504), 정상 기준선 H0(정상)와 H1(설정이 없어도 정상인 서비스). C1과 C2는 Kubernetes 객체에서 원인이 보이지 않는 시나리오다.
* 규칙 장애의 AI 조사: 평가는 A1, A3, A5처럼 규칙이 적발하는 장애에도 AI 조사를 하도록 켜서(ai_on_rules) 잰 값이다. 운영에서는 11월 9일 이후(PR #228) 규칙이 적발한 장애를 AI 조사 없이 규칙 기반 진단 결과로 끝낸다.
* 실행: 장애를 한 번 주입한 상태에서 AI 조사를 3회 연달아 돌린다. 독립된 장애 주입 3회가 아니므로 에이전트의 편차만 잰다.
* 채점 네 층: 결과(평가 러너는 원인 리소스를 코드로 대조하고, KPI는 보고서 결론과 근거를 정답 파일과 대조해 원인 지점 기준으로 채점했다. 결론 문장은 조사와 다른 모델 gpt-4.1이 채점), 과정(정답 파일의 핵심 근거를 에이전트가 도구로 직접 얻었는지), 근거(인용한 근거가 문장을 뒷받침하는지 gpt-4.1이 주장별로 채점), 금지(원인이 아닌 것을 원인으로 올렸는지).
* 실패 분류: 도구 한계(정답의 핵심 근거를 현재 도구로는 얻을 수 없음), 탐색 실패(얻을 수 있는 핵심 근거를 못 얻음), 추론 실패(근거는 다 얻었는데 원인을 틀림), 보고 실패(원인 리소스는 맞는데 결론 문장이 불일치), 근거 불일치(맞혔지만 결론이 근거로 뒷받침되지 않음).
* 사람이 직접 채점한 라벨로 gpt-4.1 채점을 보정하는 장치는 만들었으나 라벨이 0건이라 보정은 하지 못했다.

* 11/09에는 A7(서비스 주소 끝에 점이 붙은 오타) 1회도 따로 돌렸고 1/1 통과했다. 배치에 속하지 않은 단일 실행이다.
* 배치마다 시나리오 구성이 달라 원인 정확도끼리 직접 비교할 수 없다.
* 이 절의 모든 행은 원인 지점 기준(보고서가 원인 지점을 찾고 원인 서비스 또는 직접 연결된 서비스를 1순위로 지목하면 정답)이다. 원인 리소스까지 일치해야 정답으로 본 엄격 기준 결과는 `docs/learning/2026-11-11-cause-pinpoint-failures.md`에 따로 정리했다. 도구·재조사 보강의 C2는 재채점할 기록이 2회다. 전체 재평가의 B1 한 회는 B1의 500이 아니라 429를 근거로 들어 오답이었다. 6절의 최종 배포는 경로 B 장애만 집계해 이 절의 배치(규칙 장애 A1·A3·A5에도 AI 실행)와 분모 구성이 다르므로 직접 비교하지 않는다.

## 4. C1 분리 비교

C1 도구·재조사 분리 비교(11/03 01:50~02:09)에서는 C1을 한 번 주입하고, 도구 보강만 한 버전과 미해결 가설 재조사까지 포함한 버전을 같은 Pod의 별도 컨테이너에서 3회씩 돌렸다.

| 버전 | 통과 | 지목한 원인 리소스 | 판단 | 시간 중앙값 | 입력 토큰 중앙값 | 도구 호출 중앙값 |
|---|---|---|---|---|---|---|
| 도구 보강만 | 3/3 | llm-gateway 1회, agent 2회 | 후보 3 | 149.5초 | 224,974 | 15 |
| 재조사 포함 | 3/3 | agent 3회 | 후보 3 | 168.6초 | 340,615 | 20 |

* 원인 지점 기준으로는 두 버전 모두 3/3이었다. 다만 지목한 원인 리소스는 6회 중 llm-gateway 1회, agent 5회여서 원인 Pod·리소스 특정은 안정적이지 않았다. 결론 문장 채점은 6회 중 5회를 일치로 봤다.
* 표본이 작아 재조사의 단독 영향은 단정하지 않는다.
* C1은 HTTPChaos가 앱 처리 뒤에 응답을 바꾸므로 llm-gateway 자기 로그에는 429가 남지 않고, 호출한 agent 로그에만 남는다. 그래서 호출자와 호출 대상 중 어디가 원인인지 구분하기 어렵다. 이 한계를 반영해 평가 기준을 다시 정의하는 일이 열린 이슈 #182다.

## 5. C1·C2 튜닝 비교 (#75)

11월 9~10일에 튜닝 전 기준선(`c458dd6`)과 튜닝 버전에서 C1·C2를 각각 3회씩 조사했다. 시나리오별로 두 버전에 같은 모델·러너·설정을 사용했다. C2는 Redis 연결 차단 중에도 `admin` Pod가 Ready인 조건을 재현하기 위해 양쪽에 같은 TCP 준비 상태 검사를 적용했다. 조사 시간에는 장애 주입과 증상 확인 시간을 포함하지 않았다.

튜닝에서는 후속 조사 호출에 전달하는 이전의 긴 도구 응답을 줄이고, 요청이 시간 초과될 때 하위 의존성의 응답 대기를 가설로 남기도록 지침을 보강했다. 두 버전은 같은 도구 목록을 사용했다.

| 시나리오 | 지표 | 기준선 | 튜닝 |
|---|---|---:|---:|
| C1 | 원인 지점 기준 채점 | 3/3 | 3/3 |
| C1 | 결론 문장 채점 일치 | 3/3 | 2/3 |
| C1 | 입력 토큰 중앙값 | 352,853 | 266,175 |
| C1 | 조사 시간 중앙값 | 189.2초 | 186.7초 |
| C2 | 오확정 | 2/3 | 0/3 |
| C2 | 후보 판단·의존성 가설·운영자 확인 항목 충족 | 1/3 | 3/3 |
| C2 | 재조사 실행 | 1/3 | 3/3 |
| C2 | 도구 호출 중앙값 | 15회 | 20회 |
| C2 | 조사 시간 중앙값 | 122.8초 | 218.3초 |

**C1에서 확인한 사실.** 튜닝 세 회차 모두 `agent`가 `llm-gateway-svc` 호출에서 HTTP 429를 받았고, 그 응답이 채팅 실패로 이어졌다고 보고했다.

**C1에서 판단을 보류한 지점.** HTTPChaos가 앱 처리 뒤에 응답을 바꾸는 주입 방식이라 `llm-gateway` 앱 로그에는 해당 429가 남지 않는다. 주변의 200 응답도 공통 요청 식별자로 같은 요청과 연결할 수 없었다. 세 회차 모두 429의 최초 생성 지점과 실제 할당량 소진 여부를 판단 보류로 남겼다.

**C1의 원인 지점 기준 채점.** 기준선과 튜닝 모두 3/3이어서 차이가 없었다. 튜닝에서 달라진 것은 입력 토큰 중앙값이 24.6% 줄어든 점이다. 원인 리소스까지 일치해야 정답으로 본 엄격 기준 결과는 `docs/learning/2026-11-11-cause-pinpoint-failures.md`에 따로 정리했다.

**C2의 오확정 감소.** 기준선은 3회 중 2회에서 `admin`의 응답 정체를 확인한 뒤 내부 원인이 미확인인 상태에서 최종 판단을 `확정`으로 표시했다. 튜닝 버전은 기존 리소스·로그 조회 도구로 Redis까지 살펴봤고, 세 회차 모두 하위 의존성 가설과 운영자 확인 항목을 남겨 `후보`로 판정됐다. 오확정은 2건에서 0건으로 줄었고 조사 시간은 늘었다. 튜닝 버전의 한 회차가 장애 주입 전 Redis 오류 로그를 인용했으므로, 이 비교에서 확인한 개선은 오확정 감소까지다. 두 변경을 함께 적용해 각각의 효과는 분리 측정하지 않았다.

## 6. 최종 배포 버전 KPI

11월 10일 PR #245가 반영된 버전(`f97c068`)을 minikube에 배포해 측정했다. A1·A3·A5는 각각 한 번 주입해 규칙으로 진단했다. B1·C1·C2는 시나리오당 한 번 주입한 상태에서 AI 조사를 3회씩 반복했다. H0·H1은 별도 점검 3회씩 총 6회에서 조사와 알림이 없었다. C2는 기본 HTTP readiness에서 Redis 차단 후 admin이 NotReady가 되어 무효였다. #75와 같은 TCP readiness 조건으로 경로 B를 재현하고 평가 뒤 원래 HTTP readiness로 복구했다.

|---|---|---:|---:|
| A1 | S01 적발, AI 미호출 | 1.5초 (첫 알림에 규칙 결과 포함) | — |
| A3 | W02 적발, AI 미호출 | 3.1초 (첫 알림에 규칙 결과 포함) | — |
| A5 | S04 적발, AI 미호출 | 0.6초 (첫 알림에 규칙 결과 포함) | — |
